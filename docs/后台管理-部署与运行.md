# 后台管理服务 · 部署与运行手册

> 日期：2026-10-17
> 对应脚本：`server/admin-relay.sh`（中转端）、`server/admin-vpn.sh`（VPN 端）
> 上位文档：`docs/后台管理服务计划书.md`；线协议与实现参考：`docs/AdminServer-参考实现.md`

---

## 1. 组件总览

| 端 | 脚本 | 管的进程 | 默认监听 | 说明 |
|---|---|---|---|---|
| 中转服务器 | `server/admin-relay.sh` | `vpn_controller` | agent 通道 `0.0.0.0:19090`（可选 TLS）、HTTP 入口 `127.0.0.1:18081` | 接受各 VPN 服务器 agent 出站反连；白名单准入；聚合管理 API |
| VPN 服务器（每台） | `server/admin-vpn.sh` | `admin_server` + `admin_agent` | 管理 API `127.0.0.1:18080` | 本地管理 API/Web 页；agent 反连中转把管理命令转发到本机 18080 |
| 中转网页（生产入口） | `tools/webadmin/app.py` | Python 标准库 HTTP/HTTPS | 默认 `127.0.0.1:8080`；生产可 `0.0.0.0:8443` + 证书 | 浏览器访问的 HTTPS 管理页，反向代理到中转 18081 |
| 操作端（管理员） | —（浏览器 / `admin_cli` / curl） | — | 连 VPN 端 `18080`；多台集中经中转网页或 `18081` | 详见第 5 节 |

依赖关系：**agent 只依赖本机 `admin_server` 和中转的 `vpn_controller`，与 `vpn_server`（隧道数据面）完全独立**——纯测后台管理链路不需要跑 `vpn_server`，也不需要 root。

两个脚本首次运行会自动完成：依赖检查 → 编译（显式 `start` 时自动 build）→ 建目录 → 生成密钥/令牌。

## 2. 部署

### 2.1 中转服务器

方式一（推荐，机器上装 cmake/g++/libssl-dev，脚本自己编译）：

```bash
git clone <你的仓库> && cd vscode/server
./admin-relay.sh start
```

方式二（不装编译环境，只拷脚本 + 已编译好的二进制；需同架构机器）：

```bash
mkdir -p ~/relay/build && cd ~/relay
scp <源机>:/home/user/vscode/server/admin-relay.sh .
scp <源机>:/home/user/vscode/server/build/vpn_controller build/
chmod +x admin-relay.sh build/vpn_controller
./admin-relay.sh start
```

首次启动自动生成 `relay_admin_token.txt`（HTTP 入口令牌，0600）；白名单 `agents.txt` 会自动建为空文件。
公网中转需放行 TCP 19090（`ufw allow 19090/tcp`）；**18081 建议只走 SSH 隧道**，不要对公网开放。

### 2.2 VPN 服务器（每台）

```bash
# 方式一：整仓拷过去
git clone <你的仓库> && cd vscode/server
./admin-vpn.sh start

# 方式二：只拷脚本 + 二进制
mkdir -p ~/vpn/build && cd ~/vpn
scp <源机>:/home/user/vscode/server/admin-vpn.sh .
scp <源机>:/home/user/vscode/server/build/admin_server build/
scp <源机>:/home/user/vscode/server/build/admin_agent  build/
chmod +x admin-vpn.sh build/admin_server build/admin_agent
./admin-vpn.sh start
```

首次启动自动生成：`keys/server_sig.key/.pub`（Ed25519 身份密钥）与 `keys/admin_token.txt`（管理令牌，0600）。

> ⚠️ **指纹 = 白名单里的身份**。指纹由 `keys/server_sig.key` 派生，必须与中转端 `agents.txt` 里登记的一致。
> - 新机器生成的是**新密钥** → 指纹变了 → 要去中转端重新 `add-agent`；
> - 想沿用旧身份：把 `keys/server_sig.key`、`keys/server_sig.pub` 一起拷过去（`chmod 600` 私钥）。
> - 若客户端里硬编码了服务器公钥（`kServerSigPubPem`），换密钥需同步更新客户端。

### 2.3 TLS + 域名（生产必读）

中转管理入口在生产环境使用**域名 + TLS**；VPN 端 18080 仍保持环回/SSH 隧道。
管理面有两条需要保护的链路：

1. **agent → 中转（19090）**：命令与注册令牌在链路中传输，必须加密；TLS 由 OpenSSL 提供，agent 强校验中转证书和域名。
2. **浏览器 → 中转网页（8443/443）**：管理页面和 API 走 HTTPS；网页进程用 Python 标准库 `ssl`（底层 OpenSSL）。

VPN 端 `18080` 与中转 `18081` 仍只绑 `127.0.0.1`，不直接暴露公网；远程看 VPN 端页面继续用 SSH 隧道。

#### 一键方案（推荐）

域名解析生效（A 记录指向本机公网 IP）后，在 `server/` 下执行：

```bash
cd /home/user/vscode/server
sudo LETSENCRYPT_EMAIL=you@example.com ./setup-admin-domain.sh scholarvpn.homes
```

脚本会依次完成：检查 DNS/80 端口 → 安装 certbot（如缺）→ 申请证书 →
复制到 `server/tls/`（644/600）→ 写 `server/admin-domain.env` →
重启中转、VPN 管理端、网页 → 注册 certbot 续期钩子。

只检查条件、不修改任何东西：

```bash
sudo ./setup-admin-domain.sh --check scholarvpn.homes
```

证书已存在、只想复制并重启（续期钩子内部也调用这个模式）：

```bash
sudo ./setup-admin-domain.sh --reload-only scholarvpn.homes
```

下面的 ①～⑧ 是手工步骤，便于理解脚本做了什么或需要自定义时使用。

#### ① DNS

在域名服务商添加记录（示例域名 `admin.example.com`）：

```text
admin.example.com.  A      <中转服务器公网 IPv4>
```

> 当前 controller 与 agent 的监听/连接都是 IPv4；不要只给域名配 AAAA，否则 IPv6-only
> 环境会连不上（需要 IPv6 时再单独改造监听与 TUN 网段）。

- **19090 必须用 DNS-only（灰云）**，不要让 Cloudflare 等 CDN 代理；普通 CDN 橙云只代理 80/443，不支持任意 TCP 19090。
- 网页端口 8443 同样建议 DNS-only；如果套 CDN，需要 CDN 支持 8443 或改用 443。

#### ② 证书（Let's Encrypt / certbot，不自研 ACME）

```bash
sudo apt install -y certbot
# 80 端口空闲时：
sudo certbot certonly --standalone -d admin.example.com
# 80 被占用：改用 --webroot 或 DNS-01 插件，仍然用 certbot，不要手写 ACME
```

证书位置：

```text
/etc/letsencrypt/live/admin.example.com/fullchain.pem   # 证书链
/etc/letsencrypt/live/admin.example.com/privkey.pem     # 私钥（0600）
```

脚本默认以普通用户运行，需要把证书复制到可读目录（私钥只给属主）：

```bash
sudo install -d -m 750 -o "$USER" -g "$USER" /home/user/vscode/server/tls
sudo install -m 644 -o "$USER" -g "$USER" \
  /etc/letsencrypt/live/admin.example.com/fullchain.pem \
  /home/user/vscode/server/tls/fullchain.pem
sudo install -m 600 -o "$USER" -g "$USER" \
  /etc/letsencrypt/live/admin.example.com/privkey.pem \
  /home/user/vscode/server/tls/privkey.pem
```

> 证书是公开信息、私钥是敏感凭据。`server/tls/` 已加入 `.gitignore`，不要提交。

#### ③ 中转端启用 TLS

```bash
cd /home/user/vscode/server
TLS_CERT=/home/user/vscode/server/tls/fullchain.pem \
TLS_KEY=/home/user/vscode/server/tls/privkey.pem \
  ./admin-relay.sh restart
```

启动日志应出现：

```text
[controller] agent 通道 0.0.0.0:19090（TLS）...
```

`admin-relay.sh` 的 `doctor` 会打印证书主题/到期时间；证书 30 天内到期会告警。

#### ④ VPN 端用域名回连

公共 CA（Let's Encrypt）证书用系统 CA 校验（VPN 服务器需有 `ca-certificates`，Debian 默认已装）：

```bash
cd /home/user/vscode/server
RELAY_HOST=admin.example.com RELAY_TLS=1 ./admin-vpn.sh restart
```

私有 CA / 自签证书则指定信任根（**传 CA 证书，不要传服务端叶子证书**）：

```bash
RELAY_HOST=admin.example.com \
RELAY_TLS_CA=/path/to/private-ca.pem \
  ./admin-vpn.sh restart
```

如果连接地址是 IP、证书是域名，额外指定校验名：

```bash
RELAY_HOST=203.0.113.10 \
RELAY_TLS=1 \
RELAY_TLS_NAME=admin.example.com \
  ./admin-vpn.sh restart
```

agent 日志应出现：

```text
[agent] TLS 已启用，校验名=admin.example.com，信任根=系统 CA
[agent] 已接入 controller
```

#### ⑤ 中转网页启用 HTTPS

```bash
cd /home/user/vscode/tools/webadmin
python3 app.py --listen 0.0.0.0 --port 8443 \
  --tls-cert /home/user/vscode/server/tls/fullchain.pem \
  --tls-key  /home/user/vscode/server/tls/privkey.pem
```

也可以直接用封装脚本（读取 `server/admin-domain.env`）：

```bash
cd /home/user/vscode/server
./start-admin-web.sh
```

浏览器打开：

```text
https://admin.example.com:8443/
```

首次部署打开 `https://admin.example.com:8443/register`，用
`./admin-relay.sh token` 打印的中转令牌作为“初始化令牌”，创建第一个管理员；
之后在 `/login` 用账号密码登录。管理员账号存
`tools/webadmin/data/webadmin.db`（密码 scrypt 哈希、会话令牌哈希、CSRF、登录限速）。
中转令牌只由 `start-admin-web.sh` 在服务端读取，不会下发浏览器。

说明：

- 页面会自动带 `Strict-Transport-Security`（HSTS）。
- 想用标准 443：不要用 root 跑 Python；用 systemd 的 `AmbientCapabilities=CAP_NET_BIND_SERVICE`，或在前置 Nginx/Caddy 上终止 TLS，`app.py` 只绑环回 HTTP。
- 上游 `CONTROLLER_URL` 默认是 `http://127.0.0.1:18081`（环回明文，安全）；如果网页与 controller 分机，必须让 18081 只在私网/SSH 隧道可达，或在前置反向代理上终止 TLS，再让 app.py 用 `https://` + `--controller-ca`。不要把 18081 直接暴露公网。

标准 443 的 systemd 示例（必须用封装脚本启动，才能自动加载服务端中转令牌）：

```ini
# /etc/systemd/system/scholarvpn-admin-web.service
[Unit]
Description=ScholarVPN Admin Web (HTTPS)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=user
WorkingDirectory=/home/user/vscode/tools/webadmin
EnvironmentFile=-/home/user/vscode/server/admin-domain.env
ExecStart=/home/user/vscode/server/start-admin-web.sh
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now scholarvpn-admin-web
```

> 该用户需要对 `tools/webadmin/data/` 有写权限，并能读
> `server/tls/privkey.pem` 和 `server/relay_admin_token.txt`；unit 文件里不含令牌。
> 当前公网部署直接用 root（仓库在 `/root`），完整 unit 见三角色手册 4.3。

#### ⑥ 防火墙

```bash
sudo ufw allow 19090/tcp     # agent TLS 通道
sudo ufw allow 8443/tcp      # 中转网页 HTTPS（用 443 就放行 443）
# 不要放行 18080 / 18081；它们只应监听 127.0.0.1
```

云服务器安全组做同样的放行。

#### ⑦ 验证

```bash
# agent 通道证书与域名
openssl s_client -connect admin.example.com:19090 \
  -servername admin.example.com -verify_return_error \
  -CAfile /etc/ssl/certs/ca-certificates.crt </dev/null 2>&1 | \
  grep -E 'subject=|Verify return code'

# 网页 HTTPS
curl -sS -o /dev/null -w '%{http_code}\n' https://admin.example.com:8443/
# 带令牌查服务器列表
curl -sS -H "Authorization: Bearer $(./admin-relay.sh token)" \
  https://admin.example.com:8443/api/servers
```

#### ⑧ 证书续期

**手工上传的证书（DigiCert / 云厂商等）**

如果证书不是 Let's Encrypt/acme.sh 自动续期，而是从 CA 下载后上传，使用：

```bash
cd /home/user/vscode/server
sudo ./install-admin-cert.sh scholarvpn.homes /path/to/cert.pem /path/to/private.key
```

如果下载包把叶证书和中间证书分开：

```bash
sudo ./install-admin-cert.sh scholarvpn.homes cert.pem private.key chain.pem
```

脚本会校验域名、私钥匹配、证书链，备份旧证书，安装为 `tls/fullchain.pem`
和 `tls/privkey.pem`，停用 acme.sh 对该域名的自动续期，并重启 relay/网页。
续期时重新下载证书、上传、再执行一次即可。

> 当前公网部署使用的是 DigiCert 证书（含 `scholarvpn.homes` 和
> `www.scholarvpn.homes`），到期日 **2027-01-14**。到期前重新上传并由
> `install-admin-cert.sh` 安装；`www` 还需要单独添加 A 记录才会解析。

**Let's Encrypt/acme.sh 自动续期**

certbot 默认由 systemd timer 自动续期；acme.sh 由 cron 续期。续期后需要让服务重新加载证书：

```bash
# 复制新证书（与首次部署相同）
sudo install -m 644 -o "$USER" -g "$USER" \
  /etc/letsencrypt/live/admin.example.com/fullchain.pem \
  /home/user/vscode/server/tls/fullchain.pem
sudo install -m 600 -o "$USER" -g "$USER" \
  /etc/letsencrypt/live/admin.example.com/privkey.pem \
  /home/user/vscode/server/tls/privkey.pem

# 重启 controller（agent 会自动重连）
cd /home/user/vscode/server && ./admin-relay.sh restart
# 重启网页进程（如果在 systemd 下用 systemctl restart <unit>）
```

公共 CA 续期不会改变信任根，VPN 端 agent 不需要改配置；私有 CA 换根时才需要更新 `RELAY_TLS_CA`。

## 3. 首次接通（三步，顺序不能反）

```bash
# ① VPN 端：拿指纹
./admin-vpn.sh fingerprint

# ② 中转端：登记该指纹（controller 在跑会自动重启使其生效；
#    还没起过就先 ./admin-relay.sh start 一次）
./admin-relay.sh add-agent <上一步输出的64位hex>

# ③ VPN 端：一条命令起服务并接入
./admin-vpn.sh start
#   输出 "admin_agent 已接入中转" = 成功；
#   输出 "指纹不在白名单里" 并给出 add-agent 命令 = 按提示去中转端登记。
```

## 4. 日常运维

```bash
# ---------- 中转端 ----------
./admin-relay.sh start                 # 后台启动
./admin-relay.sh fg                    # 前台运行，Ctrl+C 干净退出
./admin-relay.sh stop                  # 停止（含孤儿进程兜底清扫）
./admin-relay.sh restart               # 重启（改了端口/白名单后用）
./admin-relay.sh status                # 状态 + 已接入 agent 列表
./admin-relay.sh logs                  # 跟踪日志
./admin-relay.sh doctor                # 环境自检（不启动任何东西）
./admin-relay.sh token                 # 打印 HTTP 入口令牌
./admin-relay.sh add-agent <64位hex>   # 登记指纹（自动重启生效）
./admin-relay.sh del-agent <64位hex>   # 移除指纹（自动重启生效）
./admin-relay.sh list-agents           # 查看白名单

# ---------- VPN 端 ----------
./admin-vpn.sh start                   # 后台启动 admin_server + admin_agent
./admin-vpn.sh fg                      # 前台运行，Ctrl+C 一起干净退出
./admin-vpn.sh stop                    # 停止（含孤儿进程兜底清扫）
./admin-vpn.sh restart                 # 重启
./admin-vpn.sh status                  # 状态（进程 + 端口 + 令牌文件）
./admin-vpn.sh kill                    # 强制清理：不看 PID 文件，直接按可执行名杀
./admin-vpn.sh logs admin_agent        # 跟踪日志（admin_server|admin_agent|all）
./admin-vpn.sh doctor                  # 环境自检
./admin-vpn.sh fingerprint             # 本机身份指纹
./admin-vpn.sh token                   # 管理令牌（admin_cli/curl 用）
./admin-vpn.sh build                   # 手动编译（增量）
./admin-vpn.sh rebuild                 # 清空 build/ 全量重编
```

说明：

- `start` 是幂等的：已在跑就提示跳过；端口预检只针对"不是自己 pid 文件记录"的占用者。
- `rebuild` 会清空整个 `build/`，但只重建 `admin_server` + `admin_agent`；`vpn_controller`、`vpn_server`、`admin_cli` 需要另跑 `cmake --build build -j`。
- 改了 `ADMIN_BIND/ADMIN_PORT/RELAY_HOST/...` 等环境变量后要 `restart` 才生效。

| 脚本 | 变量 | 默认 | 含义 |

| admin-vpn.sh | `RELAY_HOST` / `RELAY_PORT` | `127.0.0.1` / `19090` | 中转地址（生产填域名） |
| admin-vpn.sh | `RELAY_TLS` | `0` | `1` = agent 管理通道启用 TLS（系统 CA） |
| admin-vpn.sh | `RELAY_TLS_CA` | 空 | 私有 CA/自签证书信任根；设置后隐含启用 TLS |
| admin-vpn.sh | `RELAY_TLS_NAME` | 空 | 证书校验名；留空=`RELAY_HOST` |
| admin-vpn.sh | `BUILD_TYPE` | `Release` | 编译类型（Debug / RelWithDebInfo / 留空=无优化） |
| admin-vpn.sh | `ADMIN_TOKEN` | 空 | 直接指定管理令牌；留空则用/自动生成 `keys/admin_token.txt` |
| admin-vpn.sh | `KEYS_DIR` / `LOGS_DIR` / `RUN_DIR` | 脚本目录下同名目录 | 密钥、日志、PID 目录 |
| admin-relay.sh | `AGENT_BIND` / `AGENT_PORT` | `0.0.0.0` / `19090` | agent 通道监听（公网中转必须 `0.0.0.0`） |
| admin-relay.sh | `TLS_CERT` / `TLS_KEY` | 空 / 空 | agent 通道 TLS 证书链与私钥；必须成对设置 |
| admin-relay.sh | `HTTP_BIND` / `HTTP_PORT` | `127.0.0.1` / `18081` | 管理 HTTP 入口（仅环回） |
| admin-relay.sh | `ADMIN_TOKEN` | 空 | 直接指定 HTTP 入口令牌；留空则用/自动生成 `relay_admin_token.txt` |
| admin-relay.sh | `AGENTS_FILE` | 脚本目录下 `agents.txt` | 白名单文件 |
| webadmin/app.py | `WEBADMIN_TLS_CERT` / `WEBADMIN_TLS_KEY` | 空 | 网页 HTTPS 证书链/私钥；必须成对 |
| webadmin/app.py | `CONTROLLER_URL` | `http://127.0.0.1:18081` | 上游 controller 地址，可 `https://` |
| webadmin/app.py | `CONTROLLER_CA` | 空 | 上游 HTTPS 的私有 CA |

## 5. 操作端（管理员侧）

管理员的入口与现状一览：

| 入口 | 状态 | 直连 VPN 服务器 `:18080` | 经中转 `:18081`（多台集中） |
|---|---|---|---|
| Web 单页 | ✅ 已实现并验证 | ✅ 浏览器直接用 | ❌ 中转不托管页面（纯 API），需用 HTTP 客户端 |
| `admin_cli` | ✅ 已实现并验证 | ✅ | ❌ 只连本机 18080 |
| curl / Postman / 自研客户端 | ✅ | ✅ | ✅ 走 `/api/servers/{id}/...` |
| Qt 桌面端（计划书 5.2 规划） | ❌ 未实现 | — | — |

### 5.1 Web 单页（日常首选）

> 这一页由各 VPN 服务器的 `admin_server` 托管（18080）。**中转端的网页**是
> `tools/webadmin/app.py`，生产 HTTPS 用法见 2.3 节；两者不是同一个页面。

由各 VPN 服务器的 `admin_server` 托管，零外部依赖：

- **本机使用**：浏览器打开 `http://127.0.0.1:18080/`，首次提示输入管理令牌（在 VPN 端 `keys/admin_token.txt`，或 `./admin-vpn.sh token` 打印）。
- **远程使用**（用 SSH 隧道，勿对公网裸开 18080）：
  ```bash
  ssh -N -L 18080:127.0.0.1:18080 <user>@<vpn服务器>
  # 然后本机浏览器打开 http://127.0.0.1:18080/
  ```
- **页面功能**：公钥 hex/PEM（一键复制）、IP/端口、注册令牌 申请（数量）/列表/删除、一键导出（公钥+令牌的 JSON）。
- 注意：页面里的请求都是**同源**的，即它只能管自己那台服务器；跨多台请见 5.3。

### 5.2 命令行 admin_cli（脚本化/批量）

在 VPN 服务器本机（`server/build/admin_cli`；令牌从环境变量读，不进 shell history）：

```bash
cd /home/user/vscode/server
export ADMIN_TOKEN=$(./admin-vpn.sh token)
./build/admin_cli info          # 公钥/IP/端口
./build/admin_cli list          # 未消费令牌
./build/admin_cli gen 5         # 申请 5 个
./build/admin_cli del <token>   # 删除指定令牌
```

### 5.3 curl / 任意 HTTP 客户端（含多台集中管理）

```bash
# ---- 直连单台（在 VPN 服务器本机）----
curl -s http://127.0.0.1:18080/api/info                      # 公开：公钥/IP/端口
curl -s -H "Authorization: Bearer $(./admin-vpn.sh token)" \
     http://127.0.0.1:18080/api/tokens                        # 未消费令牌列表

# ---- 经中转集中管理：管理员只连中转一台，管所有已接入的服务器 ----
#      （在中转服务器上执行；{id} 即各 VPN 端的 ADMIN_NAME，先查 /api/servers 拿列表）
RT=$(cat relay_admin_token.txt)
curl -s -H "Authorization: Bearer $RT" http://127.0.0.1:18081/api/servers
curl -s -H "Authorization: Bearer $RT" http://127.0.0.1:18081/api/servers/vpn-1/info
curl -s -H "Authorization: Bearer $RT" http://127.0.0.1:18081/api/servers/vpn-1/tokens
curl -s -H "Authorization: Bearer $RT" -H 'Content-Type: application/json' \
     -X POST -d '{"count":1}' http://127.0.0.1:18081/api/servers/vpn-1/tokens
curl -s -H "Authorization: Bearer $RT" -X DELETE \
     http://127.0.0.1:18081/api/servers/vpn-1/tokens/<token>
```

要点：

- 经中转"生成令牌"在**目标服务器本地**生成并落盘（只过隧道传命令，不搬运令牌值）。
- 目标 agent 离线时返回 `503 {"error":"agent offline"}`，不排队。
- API 一览（详见计划书第 4 节）：`GET /api/info`（公开）、`GET /api/tokens`、`POST /api/tokens {"count":N}`、`DELETE /api/tokens/{token}`、`GET /api/export`、`GET /`（Web 页，仅 18080）；鉴权 `Authorization: Bearer <令牌>`，连续 5 次失败拉黑 60 秒后自动恢复。

## 6. 排障速查

| 现象 | 原因与处理 |
|---|---|
| `start` 报 `目录不可写 ... 属主=root` | 之前用 sudo 跑过留下 root 属主目录。按提示 `sudo chown -R $USER:$USER <脚本目录>`，或把旧 `run/` 改名保底、重建一个普通用户属主的 |
| `stop/status` 报 `仍有残留未清理（权限不足？）` | PID 属主是别人（常见 root 遗留进程）。`sudo kill <pid>`，或保留不管（脚本会如实报告，不会谎报已停止） |
| agent 反复"与 controller 断开，X ms 后重连" | 2026-10-17 修复的半帧误判 bug（`wire::recv_frame` 单次 recv 把分片当故障）——**两端二进制都要重新编译**（`admin-vpn.sh build` / 中转端 `cmake --build build --target vpn_controller`） |
| `start` 提示"端口已被占用"且 pgrep 列出的是自己的进程 | 旧版本行为；现版本先按 pid 文件判幂等。若仍遇到：`./admin-vpn.sh status` 确认后 `restart` |
| agent 日志"准入被拒: pubkey not in whitelist" | 指纹未登记/被移除：中转端 `./admin-relay.sh add-agent <指纹>` |
| agent 日志"连接 controller 失败" | 中转没起、端口不对、防火墙未放行 19090 |
| 管理接口连续 401 | 令牌错或已换；用 `./admin-vpn.sh token` 取当前令牌。失败满 5 次拉黑 60 秒（静默断连），窗口过后自动恢复 |
| Web 页提示"管理令牌无效" | 重新输入 `keys/admin_token.txt` 里的令牌 |

文件位置：日志 `logs/`（`admin_server.log`、`admin_agent.log`、`vpn_controller.log`、`admin_audit.log` 管理操作审计）；PID `run/`；密钥与令牌 `keys/`（VPN 端）、`relay_admin_token.txt`（中转端）。

## 7. 安全提醒

- 18080/18081 默认仅环回；远程访问一律走 SSH 隧道（`ssh -L`），不要绑 `0.0.0.0` 裸奔。
- 19090 是对公网的服务端口：生产必须设置 `TLS_CERT/TLS_KEY`，VPN 端用
  `RELAY_TLS=1`（公共 CA）或 `RELAY_TLS_CA`（私有 CA）校验证书与域名。
- 19090 的准入仍靠 Ed25519 指纹白名单（显式登记，不 TOFU）；TLS 不替代白名单，不登记即拒。
- 网页端 HTTPS 证书用 certbot 签发/续期，私钥权限 `0600`；不要使用 `--insecure`/跳过校验的客户端参数。
- **注册令牌 = 准入资格**，等同敏感凭据：只经带 Bearer 的管理接口分发，别贴聊天记录/工单。
- 不要用 sudo 跑 `admin-vpn.sh`（纯管理链路不需要 root；用 sudo 跑会把 `run/`、`logs/` 弄成 root 属主，之后普通用户管不动）。
