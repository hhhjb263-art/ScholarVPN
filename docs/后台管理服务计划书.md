# 后台管理服务计划书（Admin Service）

> 状态：待实现
> 日期：2026-09-28
> 范围：**只做三件事** —— 公钥显示、IP/端口显示、注册令牌分发（申请/查看/删除）。不含在线人数、会话明细、状态统计。
> 管理端客户端：**Web 网页版**（随服务端内嵌交付）+ **Qt 桌面版**（独立小工程），两者调用同一套 API。
> 目标架构：多台 VPN 服务器时采用「**vpn_controller 控制面 + Agent 反连**」集中管理（见 3.5）；一期落地的 AdminCore/本地 API 是其直接复用的执行层。

---

## 1. 背景与目标

当前服务端的管理操作只有一种途径：SSH 登录服务器执行 `./build/vpn_server --gen-token [n]`（`server/main.cpp`），查公钥也要去 `keys/` 目录翻文件。

本计划新增一个**后台管理服务**，提供：

| 功能 | 说明 |
|---|---|
| 公钥显示 | 返回服务器 Ed25519 身份公钥（PEM + 64 位 hex），供配置客户端用 |
| IP / 端口显示 | 返回当前监听 IP 与端口 |
| 令牌分发 | 页面点「申请」按钮 → 服务器生成指定数量的令牌**追加**至 `register_tokens.txt`；支持**查看**未消费令牌列表与**删除**未使用令牌 |

## 2. 现状梳理（相关代码位置）

| 现有机制 | 位置 | 与本方案的关系 |
|---|---|---|
| `--gen-token [n]` CLI 生成令牌 | `server/main.cpp:100-190` | Admin 侧**原样复制**其 flock+追加块（CLI 一行不动）；生成函数直接复用现成符号 |
| 令牌消费（注册成功删行） | `server/UDP/UDP.cpp`（`file_remove_line` 原子替换） | 删除令牌复用同款"原子重写"语义 |
| 跨进程互斥约定 | `flock <register_tokens.txt>.lock` | **硬约束**：CLI 短进程、运行中服务端、管理服务三方都必须遵守 |
| keys 目录推导规则 | `parent(key_sig_path)`（`main.cpp` 注释有前车之鉴） | 管理服务必须复用同一规则，否则 systemd 下 cwd 不同会写错目录 |
| 公钥文件 | `keys/server_sig.pub`（首次启动自动生成） | 管理服务直接读此文件，**不碰** `VpnCore` |

## 3. 方案总览

### 3.1 部署形态

**内嵌 `vpn_server` 进程的管理线程**，不设独立 daemon：

- 公钥/IP/端口在 `main.cpp` 的 `Config` 与 `keys/server_sig.pub` 里都有，无需跨进程通信；
- 与主服务同生命周期，systemd 无需新 unit；
- `VpnCore / UDP / TCP / TUN` **一行不改**，数据面零风险。

### 3.2 协议选型

**独立 TCP 管理端口上的极简 HTTP/1.1 + JSON，手写实现（零新依赖）。**

- 只解析：请求行 + headers + `Content-Length` + body，`Connection: close` 短连接；
- 默认监听 `127.0.0.1:18080`；
- 选择理由：curl 可直接调试、约 300 行代码、与现有运维习惯无缝。

**否决的备选**：

| 备选 | 否决原因 |
|---|---|
| 复用 51820 隧道端口 | 管理报文会闯进数据面热路径 `handle_framed`、会话表、握手限速表，协议类型空间被污染 |
| Unix domain socket | 只能本机访问，失去"后台服务"意义 |
| gRPC | 重依赖，违背项目零依赖风格 |
| HTTPS（一期） | 默认只绑环回走 SSH 隧道已安全；二期可选引入 libssl |

### 3.3 通信模型

```
浏览器 / Qt 管理端 / curl ──TCP 18080──▶ AdminServer 线程（vpn_server 进程内）
                              │  GET /            → 内置管理页（静态 HTML+JS）
                              │  GET /api/info    → 读 server_sig.pub + Config
                              │  GET/POST/DELETE  → TokenStore
                              │                      │ flock
                              │                      ▼
                              │            keys/register_tokens.txt
                              │                      ▲
                              └── 运行中服务端消费令牌（UDP.cpp file_remove_line）
                                   旧 CLI --gen-token（独立短进程）
```

数据面端口 51820 与管理端口 18080 完全隔离。

### 3.4 部署拓扑：要不要另设一台"管理服务器"？

先澄清两个概念：

1. **C/S 架构下客户端永远不需要公网 IP**——浏览器/Qt 管理端只发起出站连接，无需被任何人够到；
2. 本方案的 Web 页面**由 VPN 服务器上的 AdminServer 托管**，不在管理员电脑上；需要"被够到"的是管理 API 的宿主（当前用 SSH 隧道解决）。

真正要决策的是：**管理 API 的入口放哪、远程管理端怎么够到它**。

| 形态 | 拓扑 | 优点 | 缺点 / 硬伤 | 适用 |
|---|---|---|---|---|
| **A. 内嵌 + SSH 隧道**（本计划一期） | 管理端 → SSH → vpn_server:18080（环回） | 零新设施；sshd 久经考验；实现量最小 | 每次要开隧道，手机端不方便 | 单台服务器、管理员有 SSH |
| **B1. 独立管理服务器 + agent 反连** | vpn_server **出站**长连接 → 管理服务器（公网）；管理端 → HTTPS → 管理服务器 | VPN 服务器管理面**零入站端口**（不怕扫）；天然支持多台 vpn_server、多管理员；手机浏览器随时管理 | 多一台服务器 + 新组件（agent 通道、账号体系、HTTPS、防爆破） | 多台服务器 / 多管理员 / 移动办公 |
| B2. 独立管理服务器 + SSH 代跑 CLI | 管理服务器收到请求 → ssh 到 vpn_server 跑 `--gen-token` | vpn_server 零改动 | **覆盖不了需求**：CLI 没有"列表/删除"接口，查看与删除仍需进程内 AdminServer；输出解析脆弱、SSH 密钥管理散乱 | 不推荐 |
| C. 独立服务器当纯反代 | 管理端 → HTTPS/反代 → vpn_server:18080 | 复用 nginx/Caddy 的 TLS | 仍要把 18080 从环回暴露到反代可达网络，暴露面比 A 大、拓扑比 B1 别扭 | 不推荐 |

**关键事实**：令牌文件与公钥的事实源在 VPN 服务器上。无论管理服务器放哪，"管理服务器 ↔ VPN 服务器"之间都必须存在一条执行通道——所以**另开一台服务器并不能省掉内嵌 AdminServer/TokenStore**（B2 除外，但它覆盖不了查看/删除），只是把管理端入口从 SSH 隧道换成公网 HTTPS。

**推荐演进路径**：见 **3.5 目标架构**——一期先落地 AdminCore + 本地 HTTP（单台立即可用），二期叠加 vpn_controller + agent 反连，已实现部分零浪费。

### 3.5 目标架构：vpn_controller 控制面（多台 VPN 服务器时）

多台 VPN 服务器是 C/S 集中管理架构的明确适用场景：管理端只连一个入口，命令由中间服务器转发到各 VPN 服务器，**所有 VPN 服务器对管理面只出不进**。

```
                        ┌─────────────────────────────┐
  Web 管理端 ──────────▶ │                             │
  Qt 管理端 ──────────▶ │  vpn_controller（公网服务器） │
  curl ──────────────▶  │  · 管理 API + 静态 Web 页     │
                        │  · agent 注册表 / 指纹白名单   │
                        │  · 命令转发 + 集中审计         │
                        └───────▲───────────▲─────────┘
                                │           │
                                │  TLS 长连接（各机**出站**发起）
                     ┌──────────┴───┐  ┌────┴─────────┐
                     │ vpn_server A │  │ vpn_server B │  …可继续扩展
                     │  AdminCore   │  │  AdminCore   │
                     │  + agent 客户端│ │  + agent 客户端│
                     └──────────────┘  └──────────────┘
```

**组件职责**

| 组件 | 职责 |
|---|---|
| `AdminCore`（处理器层） | info / tokens 四个操作 + TokenStore——**唯一的令牌执行层**，所有形态共用 |
| 本地 HTTP 监听（一期） | AdminCore 的环回入口（SSH 隧道 / 本机 curl 调试用） |
| agent 客户端（二期，`vpn_server` 内） | **出站** TLS 长连接到 controller；收命令 → 调 AdminCore → 回结果 |
| `vpn_controller`（二期，新可执行） | agent 注册/准入、命令转发、管理 API 聚合（多服务器寻址）、静态 Web 托管、集中审计 |
| Web / Qt 管理端 | 只连 controller；二期增加"目标服务器"选择 |

**agent 通道协议（vpn_server → controller）**

- 传输：**TLS + 长度前缀 JSON 帧**（4 字节大端长度 + JSON 载荷）。两端都是自有代码，不引入 WebSocket/HTTP 栈；将来若要把 controller 藏到 nginx/CDN 之后，再升级 WSS；
- 准入握手：agent 连接后发 `{"type":"hello","pubkey_hex":…,"sig":Ed25519(服务器随机挑战)}`——复用 `Crypt/` 现成签名原语；controller 按**公钥指纹白名单**放行，新指纹必须管理员显式登记（`vpn_controller add-agent <指纹>`），不做信任首用（TOFU）；
- 心跳：15s 一次；断线指数退避重连（1s 起步、60s 封顶 + 随机抖动）；
- 命令帧：controller → agent `{"id":…,"method":"POST","path":"/api/tokens","body":…}`；agent → controller `{"id":…,"status":200,"body":…}`——**HTTP 语义原样过隧道**，AdminCore 处理函数零改动；
- agent 离线：controller 对该服务器的请求直接返回 `503 {"error":"agent offline"}`，**不排队**（令牌生成不应被静默延迟执行）。

**管理 API 寻址（controller 上）**

```
GET    /api/servers                      已连接 agent 列表（名称/指纹/版本/最后在线）
GET    /api/servers/{id}/info            转发 → 指定服务器
GET    /api/servers/{id}/tokens          转发
POST   /api/servers/{id}/tokens          转发
DELETE /api/servers/{id}/tokens/{token}  转发
```

**稳妥性要点（为什么多台时它更稳）**

- N 台服务器本要保护 N 个管理入口（N 份 SSH 端口/密钥/防火墙规则），收敛为 **1 个 controller 入口 + 各机零入站管理端口**；
- 鉴权、防爆破、审计集中一处：每次发令牌都能查到"哪个管理员、哪台服务器、什么时间"；
- 新增一台 VPN 服务器 = 拨号注册一次，无需改防火墙/分发 SSH 密钥；
- 故障解耦：controller 宕机只影响管理面，VPN 隧道数据面不受任何影响（agent 自动重连恢复）；controller 应部署在与 VPN 服务器不同的机器，避免共担故障。

**信任边界提醒**：controller 会在 TLS 通道内转发令牌明文，是管理面的可信核心——必须做好 HTTPS/防爆破/审计；其被攻破等于全部服务器的发令牌权沦陷。这与"每台服务器各自管钥匙"是取舍关系，多台场景下集中化的收益大于风险。

## 4. API 规范

统一错误格式：HTTP 4xx/5xx + `{"error":"..."}`。鉴权方式：请求头 `Authorization: Bearer <管理令牌>`。

### 4.1 GET /api/info —— 公钥/IP/端口（公开访问）

公钥、IP、端口本就是客户端要连接的公开信息，不设鉴权。

```json
{
  "version": "1.0",
  "pubkey_pem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n",
  "pubkey_hex": "64位十六进制",
  "ip": "0.0.0.0",
  "port": 51820
}
```

- `ip` 返回**配置的监听地址**（`cfg.listen_ip`）；配置为 `0.0.0.0` 时，字段 `"ip": "0.0.0.0"` 原样返回，由调用方自行理解为"任意网卡"，页面展示时以访问者所用的服务器地址为准。

### 4.2 GET /api/tokens —— 列出未消费令牌（鉴权）

读 `register_tokens.txt` 当前内容（即所有未被注册消费掉的令牌），每行一个。

```json
{ "tokens": ["a1b2...64hex", "c3d4...64hex"] }
```

### 4.3 POST /api/tokens —— 申请令牌（鉴权）

请求体：`{"count": N}`（1 ≤ N ≤ 1000，与 CLI 上限一致）。

行为：生成 N 个令牌**追加**至 `keys/register_tokens.txt`（`generate_register_token()` + flock），返回本次新生成的令牌。

```json
{ "tokens": ["新生成的令牌1", "..."] }
```

### 4.4 DELETE /api/tokens/{token} —— 删除令牌（鉴权）

删除**未消费**的指定令牌（撤销准入资格）。行为：flock 持有期间读全表 → 过滤该行 → 写临时文件 → `rename` 原子替换（与 `UDP::file_remove_line` 同款语义）。

- 成功：`{"deleted": true}`
- 令牌不存在（可能已被消费）：`404 {"error":"token not found"}`

### 4.5 GET / —— Web 管理端页面（公开，页面内再鉴权）

AdminServer 托管的静态 HTML+JS 单页（约 150 行，零外部依赖），是两个管理端之一，详见第 5 节。

> **CORS 说明**：页面与 API 同源（都由 AdminServer 提供），无需任何 CORS 处理；Qt 端不是浏览器，同样不受 CORS 限制。仅当将来把网页单独托管到别的域名/端口时，才需要给 API 加 `OPTIONS` 预检与 `Access-Control-Allow-Origin`（可预留 `--admin-cors-origin` 参数，本期不做）。

## 5. 管理端客户端（Web 网页版 + Qt 桌面版）

两个管理端是**纯前端差异**，后端 API（第 4 节）完全相同、不改一行。

### 5.1 Web 网页版（随服务端交付）

- **形态**：源码 `server/Admin/web/index.html`，以 C++ raw string literal **嵌入 AdminServer 二进制**（`GET /` 直接返回）——避免 systemd/CLI 部署时的路径依赖（keys 目录的前车之鉴）；将来想改成外部文件托管，只动 AdminServer 一处；
- **技术选型**：纯 HTML + CSS + 原生 JS（无框架），`fetch` 调 API；管理令牌存 `localStorage`（仅限环回/SSH 隧道场景使用）；
- **入口**：浏览器打开 `http://127.0.0.1:18080/` 即用，无需安装任何东西。

```
┌────────────────────────────────────────────┐
│  ScholarVPN 服务器管理                       │
│  ┌─ 服务器信息 ──────────────────────────┐  │
│  │ 公钥  a3f8…（64hex）      [复制]      │  │
│  │ IP    1.2.3.4                        │  │
│  │ 端口  51820                          │  │
│  └──────────────────────────────────────┘  │
│  ┌─ 注册令牌 ────────────────────────────┐  │
│  │ 数量 [5]  [申请]                      │  │
│  │ a1b2…64hex                    [删除]  │  │
│  │ c3d4…64hex                    [删除]  │  │
│  └──────────────────────────────────────┘  │
└────────────────────────────────────────────┘
```

- **鉴权**：首次打开弹输入框要管理令牌，存 `localStorage`，此后每个请求带 `Authorization: Bearer`；401 时重新弹出；
- **公钥一键复制**：hex 用于比对指纹、粘进客户端 `ServerPubKey`；
- **申请**：点按钮 → `POST /api/tokens` → 新令牌高亮显示并刷新列表；
- **删除**：每行尾部按钮 → `DELETE /api/tokens/{token}`。

### 5.2 Qt 桌面版（独立小工程）

- **形态**：**不混入 ScholarVPN 主客户端**，新建 `admin-qt/` 目录 + `AdminClient.vcxproj`，加入 `VPN_.sln` 作为第二个工程；
- **技术栈**：与主客户端同环境（VS2022 + Qt 6.9.1 msvc2022_64），新增链接 `Qt6::Network`（Qt 自带模块，不是新第三方依赖）；HTTP 用 `QNetworkAccessManager`，JSON 用 `QJsonDocument`；
- **权限**：普通用户即可（不创建网卡、不改路由），无需管理员清单；
- **不受 CORS 限制**，直接调用 4 个 API。

```
┌──────────────────────────────────────────────┐
│ 服务器 [127.0.0.1:18080]  令牌 [********] [连接] │
├──────────────────────────────────────────────┤
│ 服务器信息                                     │
│   公钥 a3f8…64hex            [复制hex][复制PEM] │
│   IP 1.2.3.4        端口 51820                │
├──────────────────────────────────────────────┤
│ 注册令牌                数量 [5]  [申请]        │
│ ┌──────────────────────────────────┬───────┐ │
│ │ a1b2…64hex                        │ [删除] │ │
│ │ c3d4…64hex                        │ [删除] │ │
│ └──────────────────────────────────┴───────┘ │
└──────────────────────────────────────────────┘
```

行为要点：

- 连接设置用 `QSettings` 记忆（地址、端口、管理令牌；令牌明文本机存放可接受，需加固可复用主客户端现成的 DPAPI 封装）；
- 一期连单台服务器的本地 API；二期增加"目标服务器"下拉（来自 controller 的 `GET /api/servers`），同一窗口管理多台；
- 公钥提供**复制 hex / 复制 PEM** 两个按钮（PEM 用于粘贴进客户端配置，hex 用于比对指纹）；
- 申请后新令牌高亮置顶；令牌行尾部或右键菜单删除；
- 401 弹窗重输令牌；连接拒绝/超时给明确中文提示（对照浏览器 `ERR_CONNECTION_REFUSED` 的场景）；
- 请求全部走异步信号槽（`QNetworkReply::finished`），不阻塞 UI 线程。

## 6. 令牌生命周期与并发控制（核心约束）

### 6.1 令牌算法（现有实现，不改动）

`Crypt/crypt.cpp:816` 的 `generate_register_token()`：

```
RAND_bytes(32 字节 CSPRNG 随机数) → 每字节转两位小写 hex → 64 字符字符串
```

没有密钥、没有派生、没有服务器端秘密——**令牌的安全性 = 256 位 CSPRNG 随机性**，`register_tokens.txt` 文件本身是唯一事实源（发一个、消费一个、删一行）。算法与位置无关，任何组件都能生成合法令牌。

### 6.2 代码复用策略（不做合并重构）

管理服务与 `main.cpp` 编进同一个二进制：生成**直接调用现成的 `generate_register_token()`**，无需重写算法；申请/追加逻辑从 `main.cpp:142-190` **原样复制**（含 flock 与 keys 目录推导），`main.cpp` 的 CLI 路径一行不动，回归风险为零。需要新写的只有 CLI 没有的两个能力：`list_tokens()`（读全表）与 `remove_token()`（flock + 原子删行）。

> **复制时唯一不可省略的是 `flock(<tokens>.lock)`**：漏掉锁的话，管理服务的追加/删除与运行中服务端的消费删行（原子 rename）并发时会互相丢数据。"算法一样"不重要，"锁一样"才重要。

**跨机提示（二期）**：令牌算法随处可复制执行，但校验与消费只认**各 VPN 服务器本地的** `register_tokens.txt`——controller 生成的令牌必须经 agent 通道落到对应服务器文件里才算数。因此二期推荐转发"生成命令"（`{"count":N}`，服务器本地生成、本地加锁写文件），而不是在 controller 生成后搬运令牌值：文件写入与锁留在事实源一侧，路径最短。

### 6.3 生命周期动作

`keys/register_tokens.txt` 是**唯一事实源**；已被注册消费的令牌由服务端自动删行，管理页列表天然只剩未消费令牌。

| 动作 | 实现 | 并发控制 |
|---|---|---|
| 申请（追加 N 行） | `generate_register_token()` 循环 + `fopen(..., "a")` | 全程持有 `flock(<tokens>.lock)` |
| 查看（读全表） | 读文件按行返回 | 读时短暂 flock |
| 删除（删一行） | 读全表 → 过滤 → 临时文件 → `rename` | flock + 原子替换 |
| 消费（服务端注册成功删行） | `UDP::file_remove_line`（现有逻辑，不改） | flock + 原子替换 |

三方（运行中服务端 / CLI 短进程 / 管理服务）共用同一把锁文件，追加与替换并发不会互相丢数据。

**keys 目录规则**：管理服务沿用 `parent(key_sig_path)`（`-k` 自定义路径、systemd 部署 cwd 不在脚本目录时都不会写错位置）。

## 7. 安全设计

| 措施 | 说明 |
|---|---|
| 默认绑定环回 | `127.0.0.1:18080`；远程管理一律 `ssh -L 18080:127.0.0.1:18080`；绑非环回时启动横幅打明文告警 |
| 管理令牌 | `--admin-token <str>` 指定；缺省自动生成 64hex 写 `keys/admin_token.txt`（0600） |
| 常量时间比较 | `CRYPTO_memcmp`，防时序侧信道 |
| 失败限速 | 鉴权失败按来源 IP 令牌桶（如 5 次/分钟，超限静默丢弃），模式参照 `UDP::allow_handshake_recompute` |
| 请求限制 | 请求头 + body 上限 8KB；读写超时 5s；`Connection: close` 短连接防连接堆积 |
| 审计日志 | 每次申请（数量）/删除（令牌指纹前 8 位）/鉴权失败，写 `logs/`（时间、来源 IP、动作） |
| 权限意识 | `vpn_server` 以 root 运行，管理令牌泄露 = 可发准入令牌，故删除/申请均留痕 |

## 9. 关键接口草案（供实现参考）

```cpp
// ServerAdmin/ServerAdmin.h —— 令牌申请（已实现并验证）
// 生成直接调 generate_register_token()（链接 Crypt 模块现成符号）；
// 追加/flock 块与 main.cpp --gen-token 同款，main.cpp 的 CLI 路径不动
std::vector<std::string> applyToken(int count,              // 1..1000
                                    std::string* err = nullptr);
// 后续补充（CLI 没有的能力）：
// std::vector<std::string> listTokens()                     读全表（未消费令牌）
// int removeToken(const std::string& token_hex)             flock + 原子删行

// Admin/AdminServer.h
class AdminServer {
public:
    struct Options {
        std::string bind_ip = "127.0.0.1";
        uint16_t    port    = 18080;
        std::string admin_token;      // 空 = 启动时自动生成并落盘
        std::string pubkey_pem_path;  // keys/server_sig.pub
        std::string listen_ip;        // /api/info 展示用
        uint16_t    listen_port;
    };
    bool start(const Options& opt);   // 失败只告警，不阻断主服务启动
    void stop();
};
```

实现要点：

- 管理服务启动失败**不应阻断 VPN 主服务**（打日志即可）；但端口被占用等要醒目提示；
- 公钥读取：`load_ed25519_public_key()` 解析 PEM 后 `EVP_PKEY_get_raw_public_key()` 得 32 字节转 hex；`server_sig.pub` 不存在时 `pubkey_*` 字段返回 null 并在页面显示"未找到公钥文件"；
- HTTP 解析仅支持 `GET/POST/DELETE`、必带 `Content-Length` 的 body，其余一律 400；
- 路由匹配精确到方法+路径，未知路径 404。

## 10. 部署与使用

```bash
# 构建
cd server && cmake -S . -B build && cmake --build build

# 启动（管理服务随主服务自动启动，默认 127.0.0.1:18080）
sudo ./build/vpn_server -a 10.8.0.1 -p 51820
# 首次启动注意控制台输出/keys/admin_token.txt 获取管理令牌

# 远程管理（推荐方式）
ssh -L 18080:127.0.0.1:18080 user@服务器IP
# 然后本机浏览器打开 http://127.0.0.1:18080/

# curl 示例
curl http://127.0.0.1:18080/api/info
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:18080/api/tokens
curl -X POST -H "Authorization: Bearer $TOKEN" -d '{"count":3}' \
     http://127.0.0.1:18080/api/tokens
curl -X DELETE -H "Authorization: Bearer $TOKEN" \
     http://127.0.0.1:18080/api/tokens/<token>

# 旧 CLI 方式保持不变（与管理服务共用 TokenStore）
sudo ./build/vpn_server --gen-token 5
```

start.sh 环境变量：`ADMIN_BIND=127.0.0.1`、`ADMIN_PORT=18080`、`ADMIN_TOKEN=...`（0/留空端口=关闭管理服务）。

Qt 管理端构建（Windows，与主客户端同一套 VS2022 + Qt 6.9.1 环境）：VS2022 打开 `VPN_.sln` → 生成 `AdminClient` 工程；普通用户权限运行即可。

## 12. 风险与注意事项

| 风险 | 对策 |
|---|---|
| root 进程新增网络面 | 默认环回 + 强制 Bearer + 限速 + 短连接 + 审计，五件套缺一不可 |
| 令牌文件三写并发 | 统一 flock 约定（第 6 节），删除走原子 rename |
| keys 目录推导错误（有前科） | 复用 `parent(key_sig_path)`，验收项专项覆盖 |
| 管理令牌泄露 = 发准入资格 | 落盘 0600、审计留痕、文档强调不要绑 0.0.0.0 裸奔 |
| 明文 HTTP | 一期仅限环回/SSH 隧道；二期可评估 libssl TLS |
