# 后台管理 Web 客户端 · 使用说明

> 给 `vpn_controller` 的 JSON API 套一层网页。
> 协议依据：`docs/客户端实现方案接口.md`
> 零依赖：只用 Python 3 标准库，**不需要 `pip install`**。

---

## 1. 它解决什么问题

`vpn_controller` 的 18081 只有极简 JSON API，**没有 Web 页**（接口文档 6.5 节自己写明）。
本工具补上网页管理端，并且解决三件麻烦事：

| 问题 | 本工具的处理 |
|---|---|
| controller 不返回 CORS 头，浏览器直接 `fetch` 会被拦 | 由本服务代理，浏览器只跟本服务同源通信 |
| 管理令牌不该放进浏览器 | 令牌留在服务端环境变量，前端拿不到 |
| controller 单线程、每请求短连接，报错难懂 | 集中超时控制 + 中文错误解释 |

```
浏览器 ──▶ app.py(:8080) ──▶ vpn_controller(:18081) ──▶ admin_agent(:19090) ──▶ admin_server(:18080)
            注入 Bearer            JSON API              反连通道              业务执行
```

## 2. 前置条件

跑之前先确认这三件事，否则页面打开也是空的：

1. **controller 在跑**
   ```bash
   ss -ltn | grep -E ':18081|:19090'
   ```
2. **拿到 controller 的管理令牌** —— 启动 controller 时 `--admin-token` 的值，
   或者 `./admin-relay.sh token` 打印出来的那个
3. **至少一台 agent 在线**
   ```bash
   curl -H "Authorization: Bearer <令牌>" http://127.0.0.1:18081/api/servers
   ```
   返回 `{"servers":[...]}` 且非空 → 可以开网页了。
   返回空 → 先解决 agent 接入（见第 6 节）。

## 3. 启动

### 3.1 本机直接跑（controller 和浏览器在同一台机器）

```bash
cd tools/webadmin

ADMIN_TOKEN=<controller 的管理令牌> python3 app.py
```

看到这些就成功了：

```
[+] 后台管理 Web 已启动: http://127.0.0.1:8080/
    中转站: http://127.0.0.1:18081
    管理令牌: 已配置（环境变量/参数）
    Ctrl+C 退出
```

浏览器打开 **http://127.0.0.1:8080/**

### 3.2 远程管理（推荐：SSH 隧道）

本服务默认只绑 `127.0.0.1`，**不要**为了省事绑 `0.0.0.0` 暴露到公网。

```bash
# 在你自己的电脑上执行，把中转服务器的 8080 映射到本地 8080
ssh -L 8080:127.0.0.1:8080 user@<中转服务器IP>
```

然后本地浏览器打开 `http://127.0.0.1:8080/` —— 流量全程走 SSH 加密。

### 3.3 常驻运行（systemd）

```ini
# /etc/systemd/system/scholarvpn-webadmin.service
[Unit]
Description=ScholarVPN 后台管理 Web
After=network.target

[Service]
Type=simple
User=user
WorkingDirectory=/home/user/vscode/tools/webadmin
Environment=ADMIN_TOKEN=改成你的令牌
Environment=CONTROLLER_URL=http://127.0.0.1:18081
ExecStart=/usr/bin/python3 app.py --port 8080
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now scholarvpn-webadmin
sudo systemctl status scholarvpn-webadmin
```

> ⚠️ unit 文件里写了令牌，记得 `sudo chmod 600` 这个文件。

### 3.4 参数与环境变量

| 参数 | 环境变量 | 默认 | 说明 |
|---|---|---|---|
| `--listen` | `WEBADMIN_BIND` | `127.0.0.1` | 监听地址 |
| `--port` | `WEBADMIN_PORT` | `8080` | 监听端口 |
| `--controller` | `CONTROLLER_URL` | `http://127.0.0.1:18081` | 中转站地址 |
| `--token` | `ADMIN_TOKEN` | 空 | controller 管理令牌 |

**令牌的两种给法**：

- **推荐**：`ADMIN_TOKEN` 环境变量 / `--token`，前端完全接触不到
- 临时排查：不配，点页面右上「**令牌**」输入 —— 存在浏览器 `sessionStorage`，
  关闭标签页即失效，每次请求经 `X-Admin-Token` 头转给本服务

## 4. 界面怎么用

### 4.1 布局

```
┌─────────────────────────────────────────────────────────┐
│ ScholarVPN 后台管理  vpn_controller   [地址] [令牌] [刷新] │
├──────────┬──────────────────────────────────────────────┤
│ 服务器    │  公钥与监听信息                                │
│ ● hk-01  │   版本 / 监听 / 指纹      [复制指纹]           │
│          │   -----BEGIN PUBLIC KEY----- …  [复制公钥 PEM] │
│          │──────────────────────────────────────────────│
│          │  未消费令牌        [数量] [申请] [导出 JSON]    │
│          │   1  7f3a91…  [复制] [删除]                    │
│          │   2  b1d4e7…  [复制] [删除]                    │
└──────────┴──────────────────────────────────────────────┘
```

### 4.2 操作对照

| 你想做什么 | 怎么操作 |
|---|---|
| 看有哪些服务器在线 | 打开页面即可，左栏自动列出（每 15 秒刷新） |
| 看某台的公钥 | 点左栏那台 → 右侧「公钥与监听信息」 |
| 复制白名单指纹 | 「复制指纹」→ 得到 64 位 hex，粘到 `admin-relay.sh add-agent` |
| 复制公钥给客户端 | 「复制公钥 PEM」→ 粘进客户端 `kServerSigPubPem` |
| 发令牌 | 「数量」填 1–1000 → 点「申请」 |
| 分发令牌 | 每条右侧「复制」 |
| 删掉发错的令牌 | 「删除」→ 确认 |
| 备份当前状态 | 「导出 JSON」→ 下载服务器信息 + 当前未消费令牌 |
| 换令牌 | 右上「令牌」→ 输入 → 保存 |
| 立即刷新 | 右上「刷新」 |

### 4.3 几个别误会的显示

| 显示 | 含义 |
|---|---|
| 绿点 | 在线。列表里**只含在线 agent**，所以没有"离线"状态 |
| `203.0.113.7 · 25d87aa460a40de6…` | agent 反连的来源 IP + 指纹前 16 位 |
| 鼠标悬停显示 `last_seen: 128374923` | **不是时间戳**。它是 controller 的单调时钟毫秒，不能格式化成日期（接口文档 2.4） |

## 5. 常见错误对照表

页面顶部红色提示条会直接给出中文解释。对照排查：

| 提示 | 谁产生的 | 怎么办 |
|---|---|---|
| **401 未授权** | controller **或** agent 侧 | 两种可能：① 页面令牌错 → 右上「令牌」重填；② agent 启动时的 `--token` 与本机 admin_server 不一致 → 看 `admin_agent` 日志 |
| **404 未找到** | controller **或** agent 侧 | 路径不认识，或令牌已被注册消费掉 |
| **413 请求过大** | 本服务提前挡 | controller 上限 8KB，别一次塞太多 |
| **502 连不上中转站** | 本服务 | controller 没起 / 地址端口写错 / 被系统代理劫持（见 6.1） |
| **503 agent 离线** | controller | 该服务器当前没连接，**不排队**。见 6.2 |
| **504 agent 超时** | controller | 命令发出去了，10 秒没回执。agent 卡住或本机 admin_server 挂了 |

## 6. 排障

### 6.1 页面能打开，但所有接口都 502

**先查系统代理。**

```bash
env | grep -i proxy
```

如果服务器上为 apt/docker 设了 `http_proxy`，Python 的 `urllib` 会把它**套到连
127.0.0.1 的请求上**，于是代理替我们回一个 502 —— 现象就是"页面正常、接口全挂"，
而且错误文案根本不来自你的程序。

本程序已经对 controller 的请求**显式禁用代理**（`app.py` 里的 `ProxyHandler({})`），
正常不会中招。**如果你自己改代码，别把这一行删掉。**

### 6.2 服务器列表是空的

按顺序排查：

1. **agent 在跑吗？**
   ```bash
   ps -ef | grep admin_agent
   tail -n 30 logs/admin_agent.log     # 找 "已接入 controller"
   ```
2. **指纹登记了吗？**
   ```bash
   cd server && ./admin-relay.sh list-agents
   ```
   对比 `./admin-vpn.sh fingerprint` 的输出，必须**完全一致**（小写、64 位）。
3. **登记后重启 controller 了吗？** 白名单只在 `start()` 读一次。
4. **是不是有多台服务器？** 一期 controller **只支持单 agent 连接**（接口文档 6.8），
   第二台会一直等第一台断开。这不是配置错误。

### 6.3 令牌申请了但 agent 反复断开

单帧上限 64KB，约 **950 个未消费令牌**触顶（接口文档 6.1）。
现象是 agent 主动断开 → 退避重连，页面上表现为 504 或连接错误。

**规避**：申请后尽快分发，别在服务器上堆着。

### 6.4 改了代码怎么生效

`index.html` 是每次请求现读的，改完**刷新浏览器**即可。
`app.py` 改了要**重启进程**。

## 7. 没有真 controller 也能看界面（演示模式）

想在没部署 controller 的机器上先看看长什么样：

```bash
cd tools/webadmin

# 终端 1：假 controller（严格按接口文档实现，含 401 / 400 / 404 分支）
python3 mock_controller.py          # 127.0.0.1:19998，令牌 goodtoken

# 终端 2：Web 管理端指向它
python3 app.py --port 8080 --controller http://127.0.0.1:19998 --token goodtoken
```

打开 `http://127.0.0.1:8080/`，能看到一台 `hk-01`、3 个令牌。

可以顺手试错误路径：

```bash
# 401：错误令牌
curl -H "X-Admin-Token: wrong" http://127.0.0.1:8080/api/servers

# 502：controller 没起（把 mock 停掉再试）
curl http://127.0.0.1:8080/api/servers
```

> `mock_controller.py` 只是联调/演示用的假数据，**不要部署到生产**。

## 8. 安全注意

1. **令牌走环境变量**，别在浏览器里长期保存；`sessionStorage` 只适合临时排查。
2. **默认只绑 `127.0.0.1`**。远程访问用 SSH 隧道，不要 `--listen 0.0.0.0`。
3. 本服务与 controller 之间是**明文 HTTP**，只在环回或可信内网使用。
4. controller 的 **agent 通道（19090）也是明文 TCP**，必须置于内网/VPN/防火墙白名单之后
   —— 这是 controller 的现状，不是本工具能解决的。
5. controller 侧**没有审计日志**（审计只在 admin_server 那侧），谁发了令牌查不到。

## 9. 已知限制

| 限制 | 说明 |
|---|---|
| 请求体 ≤ 8KB | 本服务提前按 8KB 拦，超了直接 413 |
| 无分页 | 令牌多时一次性拉全量，接近 950 条会触顶 64KB 帧 |
| `last_seen` 不可读 | 单调时钟毫秒，只能用于同一份列表内比较 |
| 无操作审计 | 依赖 controller，当前没有 |
| 仅单 agent | 一期 controller 限制，多台服务器轮流在线 |
