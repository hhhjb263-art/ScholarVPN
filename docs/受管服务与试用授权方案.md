# 受管服务模式方案（试用 / 授权 / 审计 / 黑名单）

> 状态：**已确认（2026-10-31 老板拍板，见第 7 节）**
> 日期：2026-10-31
> 前置阅读：`AI_HANDOFF.md`（红线）、`docs/客户端实现方案接口.md`（controller 现状）
> 原则：**最小改造**。能用文件和签名解决的绝不加进程，能加新进程的绝不改老进程。

---

## 0. 一页纸

客户端两种模式：

- **自建模式**（`[Service] Mode=off`，默认）：完全等于现状，不新增任何网络行为、
  看不到受管模式的任何入口。**选 1 则方案 2/3/4 对它不存在**。
- **受管模式**（`Mode=managed`）：向服务方申请试用（3 天 / 2GB），自动填入服务器列表，
  最终由服务方人工确认转正式。

数据流：

```
客户端(受管模式)                          服务方（全部走 443 出口的前台域名）
  │ 1. 机器码(哈希指纹) ──POST /trial/register──▶ broker(新 Python 服务)
  │ ◀──签名试用令牌(3天/2GB)──────────────────┘   │
  │ 2. GET server-list.ini + .sig（静态签名文件）  ├─写 register_tokens.txt（现有通道）
  │ 3. 用试用令牌走【现有注册流程】连 VPN           ├─写 registered_clients.txt 扩展字段
  │ 4. 服务端登录时校验到期，数据面累计流量超 2GB 断开 ├─读 audit 日志展示域名
  │ 5. 每次启动 GET quota.ini（签名）同步状态       └─维护 blocked_domains.txt
```

**关键设计：客户端唯一硬编码地址仍是现有的 update-policy URL。**
service 地址、服务器列表地址全部放进签名策略文件里下发——后台域名不在客户端源码里，
将来换域名只重签策略（顺带完成交接文档遗留的"策略地址分段 Base64 混淆"）。

## 1. 与红线的关系（必须先拍板）

红线 1：「webadmin / server 代码不动」。本方案的四个需求对它的依赖：

| 需求 | 零改动可做？ | 说明 |
|---|---|---|
| 机器码采集 + 试用发号 | ✅ | broker 是**新进程**，通过现有文件/controller 接口对接 |
| 3 天到期控制 | ⚠️ 待验证 | 若 server 每次登录都重读 `registered_clients.txt`，broker 直接删行即可；若启动时读入内存缓存，就需要动 server（一行改成每次登录重读） |
| **2GB 流量硬限制** | ❌ | server 目前没有按 client_id 的流量计数，绕不开 |
| **域名审计 + 黑名单** | ❌ | 采集点只能在 VPN 服务端出口（SNI/DNS 明文可见处），绕不开 |

结论：**不动 server = 只能做到"3 天到期 + 人工删号"，2GB 和审计/黑名单放弃**。
下面按"允许最小化动 server"为主方案设计，零改动方案作为降级选项。

## 2. 客户端改造（Win/Linux/Android 同构，P0 先桌面）

### 2.1 模式开关与 UI

- `config.ini` 新增 `[Service] Mode=off|managed`，默认 off。
- off：界面只有现有卡片列表（现状原样）；managed：增加「申请试用」入口。
- 状态机复用**强制更新的现成机制**：`ClientApp::set_update_blocked()` 那套闸门
  加一个同型的 `set_service_blocked(reason)` —— 试用到期/超量/被拒时
  禁连接 + 阻塞弹窗（弹窗里显示原因与申请入口）。零新机制。

### 2.2 机器码（隐私清单）

采集（全部为**非隐私**硬件事实）：

| 字段 | 用途 | 存储 |
|---|---|---|
| OS 版本 + 架构 | 展示、排障 | 明文 |
| CPU 型号 | 机器码组成 | 明文 |
| 物理内存大小(MB) | 机器码组成 | 明文 |
| 网卡 MAC | 机器码组成 | **SHA-256 加盐哈希**，不传明文 |
| 出口公网 IP | 防刷（同 IP 限注册次数） | 服务端观察所得，客户端不采集不上传 |

**明确不采集**：主机名、用户名、磁盘/主板序列号、已装软件、文件列表、
浏览历史（客户端侧永远不做流量审计）、剪贴板、定位。
机器码 = `SHA-256(salt ‖ 系统级设备标识)`（64hex）——**规则 v2（2026-10-31）**：
系统级设备标识 = Windows MachineGuid / Linux machine-id（系统安装时生成，
重启/补丁/换网卡/插拔外设都不变；仅重装系统会变 → 需重新申请试用）。
v1 曾混入 os/cpu/ram/mac——网卡有线/无线切换或系统补丁都会让同一台机器
变成新设备，违背"机器码必须是固定值"，已废弃；这些字段仅作后台人工核对展示。
现实限制（如实说明）：虚拟机/改 MAC 可伪造机器码，防刷主要靠公网 IP 限频 + 人工确认，
机器码是"核对辅助"不是"防伪保证"。

### 2.3 试用申请与令牌

1. 客户端 POST `/trial/register?fp=<64hex>&os=win-x64&cpu=...&ram=...`（GET 语义即可，
   复用 `update_fetcher` 的 HTTP 栈，不必新写 POST）；
2. broker 记录 `(fp, 公网IP, 时间)`，签发**签名试用凭据**（Ed25519，内容 =
   fp + 到期时间 + 配额字节数 + 随机 token），同时把随机 token 追加进
   **现有 `register_tokens.txt`**（flock 通道，与 `--gen-token` 同写法）；
3. 客户端拿到：签名凭据（存 config）+ 服务器列表（签名静态文件，见 2.4）；
   把 token 填进 `[Server1] RegisterToken` 走**现有注册流程**——注册即绑身份，
   之后按 `registered_clients.txt` 里的扩展字段受控。
4. 客户端每次启动拉一次签名 `quota.ini`（fp → 剩余天数/流量/状态），
   用于界面展示与提前拦截；**真正执行在服务端**，客户端只是镜子。

### 2.4 服务器列表自动填入

- broker 生成 `server-list.ini` + `.sig`（Ed25519，`scripts/sign-update-policy.py`
  加一个 `sign` 已支持任意文件）：
  ```ini
  server1 = <ip>:<port>
  pubkey1 = <该服务器签名公钥 base64>
  remark1 = 香港-01
  ```
- 客户端验签后写进现有多服务器配置（`set_server()` 链路原样复用），
  试用期内用户看到的就是"卡片已填好，点连接"。

## 3. broker（唯一新增服务，Python ~500 行）

- 独立进程、独立端口（建议 127.0.0.1 + nginx 反代到前台域名 `/svc/` 路径）、
  独立 systemd 单元。**不 import、不重启、不修改 webadmin 任何文件**。
- 职责：
  1. `/trial/register`：IP 限频（如同 IP 24h 最多 3 次）、机器码记录、发号；
  2. 生成/重签 `server-list.ini`、`quota.ini`；
  3. 试用→正式：管理员在管理页核对机器码与审计记录，点「转正式」（写扩展字段清除配额）；
  4. 维护 `blocked_domains.txt`（一行一个域名，支持 `*.example.com` 后缀匹配）；
  5. 读 audit 日志 → 按用户展示「访问过的域名」列表。
- 管理界面：broker 自带极简页（单文件 Flask，密码登录）——**或** P0 先不做页面，
  直接 SSH 看文件手工管理（更小）。

## 4. server 最小改动（需解除红线，~300 行，集中在 UDP.cpp/VpnCore.cpp）

1. **到期与配额校验**：`registered_clients.txt` 行格式扩展
   `client_id identity expire_ts quota_bytes used_bytes`（旧格式行兼容照旧放行）；
   登录时校验 expire；数据面在现有收发统计处按 client_id 累计 used_bytes，
   超量 → 断开会话并拒绝重连（拒绝原因码透传，客户端弹窗展示）。
2. **域名审计**：出口转发处（tun→WAN 方向）
   - UDP 53：解析 question 域名；
   - TCP 且 payload 首字节 0x16 0x03：按 TLS ClientHello 提取 SNI；
   - append `audit/YYYY-MM-DD.log`：`client_id domain`（只记域名，不记 URL/内容/时间戳精确到秒）。
   只取每个流的第一包，无流重组，实现 ~120 行。
3. **黑名单执行**：同一采集点匹配 `blocked_domains.txt`（启动加载 + 每分钟 mtime 重读）；
   命中 → 丢包（可选：向两侧发 RST）。server 每分钟 reload，改名单即时生效（≤60s）。
4. **QUIC 盲区对策（推荐）**：试用用户禁 UDP 443 出站 → 强制回落 TCP 可审计；
   正式用户放开。一行规则，写清在文档里让用户知情。
5. **每次登录重读注册文件**（如果现状是启动缓存）：顺带解决 3 天到期零改动兜底。

## 6. 明确不做

- 客户端侧黑名单执行（服务端执行不可绕过，客户端做了只是安慰剂）；
- 内容级审计 / 中间人解密（只看明文 SNI 与 DNS 域名）；
- 防机器码伪造的强机制（硬件指纹在本产品定位下做不了强绑定，靠 IP 限频 + 人工确认）。

## 8. 数据库与集成（终版，2026-10-31 决策后）

### 8.1 Schema（SQLite：`/var/lib/scholarvpn/service.db`，路径可配）

```sql
CREATE TABLE trials (             -- 试用/授权记录（主键=机器指纹）
  fp          TEXT PRIMARY KEY,   -- 64hex 机器指纹
  client_id   TEXT UNIQUE,        -- 发号生成的 VPN 用户名（trial-xxxxxxxx）
  token_hash  TEXT,               -- 注册令牌的 SHA-256（库泄露也不泄露明文令牌）
  os TEXT, cpu TEXT,              -- 核对用明文硬件事实
  ram_mb INTEGER, mac_hash TEXT,
  first_ip TEXT, last_ip TEXT,    -- 服务端观察的公网 IP（防刷）
  created_at INTEGER,
  expire_at INTEGER,              -- 试用到期 unix 秒；0 = 不限（正式）
  quota_bytes INTEGER,            -- 试用 2GB；0 = 不限（正式）
  used_bytes INTEGER DEFAULT 0,   -- 服务端数据面累计（server 写）
  status TEXT DEFAULT 'trial'     -- trial | approved | rejected
);
CREATE TABLE register_ip_log (    -- 同 IP 限频（默认 24h 3 次）
  ip TEXT, ts INTEGER
);
CREATE TABLE audit_domains (      -- 域名审计（server 写，webadmin 读）
  day TEXT, client_id TEXT, domain TEXT, hits INTEGER,
  PRIMARY KEY (day, client_id, domain)
);
CREATE TABLE blacklist (          -- 域名黑名单（webadmin 写，server 60s 重读）
  domain TEXT PRIMARY KEY, added_at INTEGER, note TEXT
);
```

### 8.2 访问边界（迁移约束的落点）

| 进程 | 权限 | 说明 |
|---|---|---|
| broker (Python) | 读写 trials/register_ip_log | 申请/发号/限频/审批的唯一写方 |
| vpn-server (C++) | 读 trials（fp 配额列）、写 used_bytes 与 audit_domains | 热路径本地直读，零网络依赖 |
| webadmin (Python) | 读写全部表 | 审批页/审计展示/黑名单编辑（复用 `tools/broker/db.py`） |

**所有 SQL 只允许出现在 `tools/broker/db.py` 与 server 侧 `ServiceDB` 两个模块**——
将来迁 MySQL/PostgreSQL 只改这两处，其余代码零感知。

### 8.3 注册链路（与现有机制的衔接）

1. 客户端 GET `/trial/register?fp=...` → broker 限频检查 → 生成
   `client_id=trial-xxxxxxxx` + 一次性令牌 → 写 trials + 追加
   **现有 `register_tokens.txt`**（flock 通道，server 现有注册流程原样消费）；
2. 响应 = 个人凭据 INI（fp/client_id/token/expire/quota）+ `X-Service-Signature`
   头（service.key 对响应原始字节的 Ed25519 签名，客户端验签后才入库填配置）；
3. 服务器列表 = 静态签名文件 `server-list.ini(.sig)`（broker 提供与签发，
   全员相同、可缓存）；
4. server 登录：`registered_clients.txt` 身份绑定（现有）+ trials 表
   到期/配额/状态校验（新增）；不在 trials 里的用户 = 手工建的老用户，不限。
