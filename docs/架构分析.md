# ScholarVPN 架构分析

> 范围说明：本文基于源码通读整理，覆盖 **Windows 客户端（`src/`、`Config.*`、`Crypt.*`）** 与 **Linux 服务端（`server/`）** 两条核心链路。
> 未纳入核心分析：`ServerAdmin/`（服务端管理工具）、`android/`（Android 客户端）、`third_party/`、`dist/`、`x64/`、`VPN_/`（均为第三方或构建产物）。
> 结论均以代码为依据；无法确认处已明确标注。

## 一、项目概览

### 1.1 主要功能
自研隧道 VPN（仅限学习研究）：
- 客户端在 Windows 上创建 **Wintun 虚拟网卡**，把本机流量封装进自定义协议报文，经 **UDP 或 TCP** 发往服务器；
- 服务端在 Linux 上通过 **TUN 网卡**（`/dev/net/tun`）把流量转发到真实网络，回程流量反向封装回客户端；
- 两端共用一套自研隧道协议：自定义 12 字节报文头 + **三阶段身份认证** + 心跳保活；加密基于 OpenSSL（Ed25519 身份 + 临时 X25519 ECDH + HKDF + AES-256-GCM）。
- 服务端为**多用户 Session 模型**：按客户端来源地址隔离会话，自动分配虚拟 IP，支持同身份互踢、并发上限与超时清理。

### 1.2 程序入口
| 端 | 入口 | 说明 |
|---|---|---|
| 客户端 | `src/main.cpp` → `main()` | `QApplication` → 加载 `style.qss` → `Logger::Init()` → `QtWidgetsClass w; w.show()` → `a.exec()`。工程为 Windows 子系统（`VPN_.vcxproj`：`SubSystem=Windows`、`EntryPointSymbol=mainCRTStartup`） |
| 服务端 | `server/main.cpp` → `main()` | `umask(077)` → `parse_args()` → `VpnCore::init()` / `start()` → `pause()` 等信号 → `stop()`。可执行文件 `vpn_server`（`server/CMakeLists.txt`） |

## 二、架构与模块

### 2.1 总体架构
```
┌──────────────── 客户端 (Windows) ────────────────┐        ┌──────────── 服务端 (Linux) ────────────┐
│ GUI (QtWidgetsClass)                             │        │ main.cpp (CLI)                        │
│   │ 信号槽                                        │        │   │                                   │
│ AppBridge (QObject, worker QThread)              │        │ VpnCore (TUN↔UDP 桥接, 2 转发线程)    │
│   │                                              │        │   ├── Tun (Linux /dev/net/tun)        │
│ ClientApp (init/start/stop, 2 桥接线程)          │        │   ├── UDP (会话表/认证/加密/心跳)     │
│   ├── WintunTun / AdapterConfig / RouteManager   │        │   │    └── Session × N (VIP/密钥)     │
```

### 2.2 客户端模块职责
| 模块 | 文件 | 职责 |
|---|---|---|
| GUI | `src/gui/QtWidgetsClass.*` | 主窗口：当前服务器卡片（连接/断开/管理）、60 秒实时速率曲线（`SpeedChart`）、Switch Server 覆盖层、增删改服务器、写回 `config.ini` |
| 桥接 | `src/gui/AppBridge.*` | `QObject` 封装 `ClientApp`；把 worker 线程回调转成 Qt 信号（`stateChanged/connected/logappend/tokenRejected`），保证 UI 线程安全 |
| 核心编排 | `src/client/ClientApp.*` | `init()`（配置/身份密钥/网卡/路由/公钥）、`start()`（状态机 + 两条桥接线程）、`stop()`；`set_server()` 切换服务器；连接成功回调里加默认路由 + 防 DNS 泄漏 + 采用虚拟 IP + 清注册令牌 |
| 状态机 | `src/reconnect_manager.*` | `ConnState` 五态（Stopped/Connecting/Connected/Reconnecting/Error）；`worker_loop()` 建连→监视→重连，指数退避 500ms→1s→2s→5s，连续 5 次失败置 Error |
| 隧道基类 | `src/UDP.*` | 三阶段认证、AES-256-GCM 收发、心跳、收发队列；传输差异抽成 4 个虚钩子（`open_socket/establish/raw_send/recv_frame`）+ `proto_version()` |
| 隧道子类 | `src/tcp.*` | 覆写钩子实现流式 socket；`take_frame/recv_frame` 做粘包/半包分帧；版本字节 `v_tcp` |
| 协议 | `src/tunnel_protoco.h` | `tunnel_header`（magic/version/type/payload_len/sequence）、`type` 枚举（握手/数据/心跳/身份）、握手常量 |
| 密码学 | `Crypt.h/Crypt.cpp` | `generate_ed25519_keypair`、`ed25519_sign/verify`、`ecdh_derive_shared_secret`、`hkdf_*`、`aes256_gcm_seal/open`（零拷贝热路径）、`generate_nonce/register_token`、`derive_directional_session_keys` |
| 系统集成 | `tun.* / AdapterConfig.* / route_manager.* / DnsLeakGuard.*` | Wintun 网卡、网卡地址/MTU/DNS、路由（默认路由 + 服务器 bypass）、防 DNS 泄漏 |
| 配置 | `Config.h/Config.cpp` | 读写 `%APPDATA%\ScholarVPN\config.ini`；多服务器 `[Server] Count` + `[ServerN]` |

### 2.3 服务端模块职责
| 模块 | 文件 | 职责 |
|---|---|---|
| 入口 | `server/main.cpp` | CLI 解析（`-l/-p/-a/--prefix/--mtu/-k/--max-clients/--transport/-g/--quiet`）；`--gen-token` 生成一次性注册令牌（flock 跨进程锁）后退出 |
| 核心 | `server/core/VpnCore.*` | `init()` 建 TUN + 配地址 + 加载服务器身份密钥 + `udp.start()` + `tcp.start()`；`start()` 起两条转发线程；`stop()` 逆序清理 |
| 会话/认证 | `server/UDP/UDP.*` + `Session.h` | 会话表（`peer_key → Session`）、三阶段认证、注册/登录数据库、虚拟 IP 池、反重放、心跳、限速 |
| TCP | `server/TCP/tcpserver.*` | epoll 单线程事件循环管理全部连接；会话/认证/加密复用 `UDP` 类；`Session.tcp_drop` 请求断开，事件线程唯一 `close` |
| 系统 | `tun/tun.*`、`LinuxAdapter/` | TUN 设备、网卡地址/MTU/路由 |

### 2.4 依赖关系（要点）
- 客户端：Qt 6.9.1（`VPN_.vcxproj` 引用 `D:\Qt\6.9.1\msvc2022_64`）、OpenSSL 3.5.6（`third_party/openssl`，链接 `libcrypto.lib`，运行需 `libcrypto-3-x64.dll`）、Wintun 0.14.1（运行需 `wintun.dll`）、WinSock2/iphlpapi/dnsapi。
- 服务端：Linux 内核头文件（`linux/if_tun.h` 等）、CMake ≥ 3.16 + C++17、pthread、OpenSSL（`OpenSSL::Crypto`）。
- **协议一致性约束**：`src/tunnel_protoco.h` 与 `server/Buffer/tunnel_protoco.h` 必须保持一致；`Crypt.h/Crypt.cpp` 与 `server/Crypt/crypt.cpp` 线格式必须一致。版本字节（`v_udp=1`/`v_tcp=2`）即传输标识，用于丢弃错误传输的报文。

## 三、核心调用链

### 3.1 客户端启动 → 建连（控制面）
```
用户点击「连接」[QtWidgetsClass.cpp]
 → QMetaObject::invokeMethod(m_bridge, connect_to_server(entry), QueuedConnection)
 → AppBridge::connect_to_server(entry)                         [src/gui/AppBridge.cpp]
 → ClientApp::init()                                          [src/client/ClientApp.cpp]
      ├─ 加载/生成 Ed25519 身份密钥（DPAPI 加解密 client.id.enc）
      ├─ 载入服务器公钥（内置 kServerSigPubPem，可被条目 ServerPubKey 覆盖）
      ├─ Config::LoadClientConfig()  读 config.ini
      ├─ WintunTun::init_tun()       建虚拟网卡
      ├─ AdapterConfig::set_IPv4_address/set_MTU/set_metric/set_DNS_IPv4
      └─ RouteManager::add_server_bypass_route()  握手包走物理网卡
 → ClientApp::set_server(entry)  切换 IP/端口/传输/ClientID/RegisterToken/公钥
 → ClientApp::start()
      ├─ ReconnectManager(remote, port); set_transport(); set_identity()
      ├─ 注册 state / connected / tokenRejected 回调
      ├─ ReconnectManager::start() → worker_loop()              [src/reconnect_manager.cpp]
      └─ 起桥接线程 tun_to_udp_loop() / udp_to_tun_loop()
```

### 3.2 三阶段身份认证（客户端 ↔ 服务端）
```
[阶段1a] 客户端 UDP::send_work()
   send_packet(m_auth_hello, nonce_c)
 → 服务端 UDP::recv_work() → get_or_create_session(addr,false)
 → handle_framed() → handle_auth_hello()                       [server/UDP/UDP.cpp]
      ├─ generate_nonce(nonce_s) + generate_ephemeral_x25519()
      └─ ed25519_sign(nonce_c||nonce_s||DH_SRV_PUB) → 缓存 server_hello_payload
   send_packet(m_auth_server_hello, nonce_s||DH_SRV_PUB||sig_srv)
 → 客户端 handle_frame(m_auth_server_hello)
      └─ ed25519_verify(m_server_sig_pub, ...)  ← 失败=疑似中间人，断开
         → m_server_hello_ok = true

[阶段1b/2] 客户端 generate_ephemeral_x25519() → send_packet(m_auth_client_hello, DH_CLI_PUB)
 → 服务端 handle_auth_client_hello()
      ├─ ecdh_derive_shared_secret(dh_srv_priv, DH_CLI_PUB)
      ├─ derive_directional_session_keys(ss, nonce_c, nonce_s)
      │     → key_c2s(收解密) / key_s2c(发加密)
      ├─ EVP_PKEY_free(dh_srv_priv)   ← 前向安全，临时私钥立即销毁
      └─ hs_stage = HS_STAGE_KEYS; enc_ready = true
   客户端并行：ecdh + HKDF → m_key_c2s/m_key_s2c；m_enc_ready = true

[阶段3] 客户端 build_identity_message() → ed25519_sign
   send_packet(m_identity)  ← 已 AES-GCM 加密
 → 服务端 handle_framed() → aes256_gcm_open(key_c2s) → replay.accept
 → handle_identity()
      ├─ 会话绑定校验（nonce_c/nonce_s/DH 公钥须与本会话一致）
      ├─ ed25519_verify(cli_pub, ...)
      ├─ 注册分支：file_remove_line(register_tokens.txt) 作废令牌
      │             + file_append_line(registered_clients.txt)
      │  登录分支：file_contains_line(registered_clients.txt)
      ├─ 同身份互踢：按 cli_pub_hex 找旧会话 → release_session()
      ├─ allocate_virtual_ip() → m_vip_to_key[vip] = peer_key
      └─ authenticated/handshaked = true; hs_stage = HS_STAGE_AUTHED
   send_packet(m_identity_ok, [vip(4)][prefix(1)])
 → 客户端 handle_frame(m_identity_ok)
      └─ m_authenticated = true; m_assigned_ip / m_assigned_prefix
         → m_handshaked = true
```

### 3.3 数据面上行（本机 → 互联网）
```
应用(浏览器) → 系统路由(默认路由→TUN) → Wintun 网卡
 → ClientApp::tun_to_udp_loop()                                [src/client/ClientApp.cpp]
      WintunTun::read_packet() → 过滤非 IPv4 → UDP::send_ip_packet(buf)
 → UDP::m_sendqueue                                             [src/UDP.cpp]
 → UDP::send_work() 弹出 → send_packet(m_data, ...)
      └─ aes256_gcm_seal(key_c2s, inner_type||payload, AAD=帧头) → raw_send(sendto/send)
 → 服务端 UDP::recv_work() recvfrom → get_or_create_session → handle_framed()
      ├─ aes256_gcm_open(key_c2s) → replay.accept(seq)
      ├─ tunnel_packet_source_ok()  ← 源 IP 必须 == 本会话虚拟 IP（防冒用）
      └─ m_queue_recv.push() → wake_recv_waiters()
 → VpnCore::forward_udp_to_tun() → Tun::write_buf()            [server/core/VpnCore.cpp]
 → 内核按路由/NAT 送出 → 互联网
```

### 3.4 数据面下行（互联网 → 本机）
```
互联网 → 内核路由到 10.8.0.x → TUN 网卡
 → VpnCore::forward_tun_to_udp() → Tun::read_buf()
 → UDP::forward_tun_packet(buf)                                 [server/UDP/UDP.cpp]
      ├─ 解析 IPv4 目的地址 dst_net
      ├─ m_vip_to_key[dst_net] → 会话 key → m_sessions[key]
      └─ session->send_queue.push() → wake_send_waiters()
 → UDP::send_work() → send_packet(m_data) aes256_gcm_seal(key_s2c) → sendto(客户端)
 → 客户端 UDP::recv_frame() → handle_frame()
      ├─ aes256_gcm_open(key_s2c) → replay.accept(seq)
      └─ m_recvqueue.push()
 → ClientApp::udp_to_tun_loop() → WintunTun::write_packet()
 → 操作系统协议栈 → 应用
```

### 3.5 心跳与断线重连
```
心跳：客户端 send_work 每 1s 发 m_heart；服务端 reply_heartbeat() 回 m_heart_response
      服务端 heartbeat_work 每 10s 主动发心跳；30s 未收到已认证报文 → 销毁会话
      客户端 5s 未收到通过认证的报文 → m_need_reconnect = true
重连：UDP::m_need_reconnect → ReconnectManager::worker_loop() 监视循环(50ms tick)
      检测 !is_handshaked()||needs_reconnect()
 → teardown_current_locked()（stop 旧 UDP 实例）
 → set_state(Reconnecting) → ClientApp 状态回调：
       remove_default_route() + DnsLeakGuard::restore()（恢复物理网卡 DNS）
 → 退避(500ms→…→5s) 后 connect_once() 建全新 UDP 实例
       （新会话=新密钥=新反重放窗口）；连续 5 次失败 → set_state(Error) 弹窗
```

### 3.6 TCP 传输链路（UDP 丢包时的备用通道）
```
客户端：ReconnectManager::connect_once() → new TCP(...)（继承 UDP）
      UDP::init() → open_socket(SOCK_STREAM) → establish(connect+TCP_NODELAY)
      send_packet() → raw_send(send_all 循环写, 5s 上限)
      recv_work() → recv_frame() → take_frame() 分帧 → handle_frame()
服务端：TCPServer::event_loop() (epoll_wait)                   [server/TCP/tcpserver.cpp]
      → handle_accept() → get_or_create_session(peer, true) → s.tcp_fd
      → read_conn() 排空缓冲 + 分帧 → UDP::handle_framed()（与 UDP 共用）
      → flush_conn_tx()：搬运 Session.tcp_tx → 非阻塞 send，EAGAIN 订阅 EPOLLOUT
      跨线程唤醒：UDP::send_packet() 入队后 tcp_tx_wake() → eventfd → 事件线程
      断开：其他线程置 Session.tcp_drop → 事件线程 drop_conn() 统一 close
```

## 四、关键注意事项

### 4.1 启动流程与前置条件
- **客户端**：需管理员权限（清单要求）；运行目录需 `wintun.dll`、`libcrypto-3-x64.dll`、`style.qss`（PostBuild 自动拷贝）；首次运行生成 `%APPDATA%\ScholarVPN\keys\client.id.pub`（明文公钥）与 `client.id.enc`（DPAPI 加密私钥）；`config.ini` 首次运行自动生成。
- **服务端**：需 root（创建 TUN）；首次运行自动生成 `keys/server_sig.key` / `server_sig.pub`；需把 `server_sig.pub` 内容硬编码进客户端 `kServerSigPubPem`（`src/client/ClientApp.cpp`），否则阶段1 验签失败（现象酷似"被服务器踢掉"）。
- 服务端启动顺序：`VpnCore::init()`（TUN→地址→密钥→`udp.start`→`tcp.start`）→ `start()`（转发线程）→ `pause()`；`stop()` 逆序：先停转发线程，再 `udp.stop()`，再 `tcp.stop()`。

### 4.2 关键配置
- 客户端 `config.ini`：`[Server] Count=N` + `[ServerN]`（`Name/ServerIP/ServerPort/Transport/ClientID/RegisterToken/ServerPubKey`）+ `[Network]`（`VirtualIP/VirtualPrefix/DNS/MTU/Metric`）。`Transport`：0=UDP（默认）、1=TCP。
- 服务端 CLI：`-l/-p/-a/--prefix/--mtu/-k/--max-clients/--transport both|udp|tcp/-g/--quiet`；`start.sh` 支持环境变量覆盖与 systemd 安装。
- Debug/Release 差异：Debug 无服务器条目时回退 `192.168.1.12`，Release 回退空（须先添加服务器）。

### 4.3 安全机制（代码实现要点）
- 身份：服务器持久 **Ed25519**（`SIG_SRV_PRI/PUB`，客户端内置公钥验签防中间人）；客户端持久 Ed25519（私钥 DPAPI 加密，磁盘不落明文）。
- 会话：临时 **X25519 ECDH + HKDF** 派生方向性密钥（`key_tx`/`key_rx`），数据面 **AES-256-GCM**（AAD=帧头），支持前向安全。
- 防护：反重放滑窗（`ReplayWindow`，先 `too_old` 预检、GCM 验证后再 `accept`）；隧道内源地址绑定校验（`tunnel_packet_source_ok`）；握手重算令牌桶限速（`allow_handshake_recompute`）；未认证会话配额（`kMaxPendingSessions=32`）+ 每源上限（`kMaxSessionsPerIp=3`）+ 会话上限（`--max-clients`）；同身份按公钥互踢；密钥寿命上限 24h、序号上限 2^31 触发换会话。

### 4.4 外部依赖与平台约束
- 客户端仅 Windows（Wintun + WinSock2 + iphlpapi/dnsapi）；服务端仅 Linux（`linux/if_tun.h` 等）。许可注意：Wintun 源码 GPLv2、预编译二进制单独许可；OpenSSL 许可见 `third_party/openssl/LICENSE`。
