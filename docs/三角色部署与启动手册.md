# ScholarVPN 三角色部署与启动手册

> 适用版本：当前已部署的 TLS/域名版本（`3938192` + 后台管理 TLS 改动）
> 示例域名：`scholarvpn.homes`
> 示例公网服务器：`154.36.166.113`（Ubuntu 24.04，当前中转端与 VPN 端同机）
> 原则：**只把管理面暴露到域名 443；VPN 数据面仍走 51820；18080/18081 永远只绑环回。**

---

## 0. 最快上手（当前同机部署）

```bash
# 中转端（443 网页 + 19090 agent TLS）
sudo systemctl start scholarvpn-admin-relay scholarvpn-admin-web

# VPN 端管理面（18080 环回 + agent）
sudo systemctl start scholarvpn-admin-vpn

# VPN 数据面（51820，若还没跑）
cd /root/ScholarVPN/server && sudo ./start.sh -d
```

客户端只填 **VPN 服务器公网 IP** 和 `51820`；管理员浏览器打开：

```text
https://scholarvpn.homes/
```

网页不开放注册。首个管理员在服务器上创建：

```bash
cd /root/ScholarVPN/tools/webadmin
python3 manage.py create-admin admin
# 按提示输入密码（至少 10 位）
```

然后在 `https://scholarvpn.homes/login` 登录。之后可在右上角“账号”修改
自己的密码，在“管理员”里添加其他账号。

完整说明见下文。

## 1. 三个角色

| 角色 | 跑什么 | 对外端口 | 说明 |
|---|---|---|---|
| **中转端（Relay）** | `vpn_controller` + 管理网页 `app.py` | `443/TCP`（网页）、`19090/TCP`（agent TLS） | 有域名和正式证书；浏览器管理入口 |
| **VPN 端（VPN Server）** | `vpn_server` + `admin_server` + `admin_agent` | `51820/UDP+TCP`（客户端）、`18080` 仅环回 | `vpn_server` 是数据面；`admin_*` 是管理面 |
| **客户端（Client）** | Windows / Android 客户端 | 主动连 VPN 端 `51820` | 只连 VPN 端，不连中转域名 |

管理面的调用链：

```text
浏览器 ──https://scholarvpn.homes:443──▶ 中转端 webadmin
                                             │ 127.0.0.1:18081
                                             ▼
                                      vpn_controller
                                             ▲ 19090/TCP TLS
                                             │ agent 出站反连
                                      admin_agent（VPN 端）
                                             │ 127.0.0.1:18080
                                             ▼
                                      admin_server（VPN 端）
```

数据面：

```text
客户端 ──51820/UDP 或 TCP──▶ vpn_server（VPN 端）──▶ TUN ──▶ 互联网
```

> 当前部署中，中转端和 VPN 端在同一台 `154.36.166.113` 上；`admin_agent` 用
> `RELAY_HOST=127.0.0.1` 回连。分离部署时把 `RELAY_HOST` 改成中转域名即可。

## 2. 端口与访问关系

| 来源 | 目标 | 端口/协议 | 用途 |
|---|---|---|---|
| 浏览器 | 中转端 | `443/TCP` | 管理网页 HTTPS |
| VPN 端 `admin_agent` | 中转端 `vpn_controller` | `19090/TCP` | 管理命令通道（TLS） |
| 客户端 | VPN 端 `vpn_server` | `51820/UDP+TCP` | VPN 隧道（默认 UDP，可切 TCP） |
| 管理员/本机 | VPN 端 `admin_server` | `18080/TCP` 仅 `127.0.0.1` | 本地管理页/API |
| 本机 webadmin | 中转端 `vpn_controller` | `18081/TCP` 仅 `127.0.0.1` | 网页反代上游 |
| certbot/acme.sh | 中转端 | `80/TCP` | HTTP-01 签发/续期（可关） |

防火墙/安全组只需放行：

```bash
sudo ufw allow 443/tcp
sudo ufw allow 19090/tcp
sudo ufw allow 51820/udp
sudo ufw allow 51820/tcp
# 用 certbot HTTP-01 时再放行 80/tcp
```

**不要放行 18080、18081。**

## 3. 通用准备

### 3.1 系统依赖

Ubuntu/Debian：

```bash
sudo apt update
sudo apt install -y git cmake g++ make libssl-dev openssl curl python3
```

### 3.2 代码位置

当前公网服务器：

```text
/root/ScholarVPN
```

本地开发机：

```text
/home/user/vscode
```

> 代码版本注意：后台管理 TLS/域名改动目前是部署副本里的本地改动，
> 未提交到 GitHub。重新 `git clone` 后如果 `server/CMakeLists.txt` 里没有
> `OpenSSL::SSL`，说明拿到的是旧版，不能直接用本手册的 TLS 命令。
> 检查：
>
> ```bash
> grep -q 'OpenSSL::SSL' server/CMakeLists.txt && echo TLS版 || echo 旧版
> ```

### 3.3 构建

在需要的机器上执行（中转端只需要管理组件；VPN 端还需要 `vpn_server`）：

```bash
cd /root/ScholarVPN/server
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

# 中转端 + VPN 管理面
cmake --build build --target admin_agent vpn_controller admin_server admin_cli -j"$(nproc)"

# VPN 数据面（如果这台机器要跑 vpn_server）
cmake --build build --target vpn_server -j"$(nproc)"
```

生成的二进制：

```text
server/build/vpn_controller   中转端
server/build/admin_agent      VPN 端 agent
server/build/admin_server     VPN 端本地管理 API
server/build/admin_cli        VPN 端命令行工具
server/build/vpn_server       VPN 数据面
```

### 3.4 DNS

在域名服务商添加：

```text
scholarvpn.homes      A    <中转服务器公网 IPv4>
www.scholarvpn.homes  A    <中转服务器公网 IPv4>   # 可选
```

- `19090` 必须用 **DNS-only（灰云）**，不要让普通 CDN 代理任意 TCP。
- 如果中转和 VPN 是两台机器，客户端连接的是 **VPN 服务器 IP**，不是中转域名。

## 4. 角色一：中转端部署

以下命令默认在 `/root/ScholarVPN/server` 执行。

### 4.1 目录与证书

```bash
cd /root/ScholarVPN/server
mkdir -p tls logs run
chmod 700 tls
```

证书需要两个文件：

```text
tls/fullchain.pem   证书链（叶证书 + 中间证书），0644
tls/privkey.pem     私钥，0600
```

#### 方式 A：手工上传的证书（当前使用，DigiCert）

从 CA/云厂商下载证书后，上传到服务器，然后执行：

```bash
cd /root/ScholarVPN/server
sudo ./install-admin-cert.sh scholarvpn.homes \
  tls/scholarvpn.homes.pem tls/scholarvpn.homes.key
```

如果叶证书和中间证书分开：

```bash
sudo ./install-admin-cert.sh scholarvpn.homes cert.pem private.key chain.pem
```

脚本会校验域名、私钥、证书链，备份旧证书，安装到
`tls/fullchain.pem` / `tls/privkey.pem`，停用 acme.sh 对该域名的自动续期，
并重启 relay/网页。

#### 方式 B：Let's Encrypt（自动续期）

```bash
cd /root/ScholarVPN/server
sudo LETSENCRYPT_EMAIL=you@example.com \
  ./setup-admin-domain.sh scholarvpn.homes
```

脚本会检查 DNS/80、安装 certbot、申请证书、写配置、重启服务并注册续期钩子。

只检查条件：

```bash
sudo ./setup-admin-domain.sh --check scholarvpn.homes
```

> 当前公网服务器使用 DigiCert 证书，到期 **2027-01-14**；到期前重新上传并用
> `install-admin-cert.sh` 安装。

### 4.2 中转端配置 `admin-domain.env`

同机部署（中转 + VPN 在一台机器）示例：

```ini
DOMAIN=scholarvpn.homes

TLS_CERT=/root/ScholarVPN/server/tls/fullchain.pem
TLS_KEY=/root/ScholarVPN/server/tls/privkey.pem

# 同机 agent 回连本机，但按域名校验证书
RELAY_HOST=127.0.0.1
RELAY_TLS=1
RELAY_TLS_NAME=scholarvpn.homes

# 网页
WEBADMIN_BIND=0.0.0.0
WEBADMIN_PORT=443
WEBADMIN_TLS_CERT=/root/ScholarVPN/server/tls/fullchain.pem
WEBADMIN_TLS_KEY=/root/ScholarVPN/server/tls/privkey.pem
CONTROLLER_URL=http://127.0.0.1:18081
```

权限：

```bash
chmod 600 admin-domain.env
```

> `ADMIN_TOKEN` 现在只作为**服务端**访问 controller 的令牌，由
> `start-admin-web.sh` 自动读取，不会下发浏览器。公网访问由管理员账号 +
> 服务端会话控制；不要再设置 `WEBADMIN_AUTO_TOKEN`（已废弃）。

分离部署时：

- 中转端 `admin-domain.env` 只需要 `TLS_CERT/TLS_KEY` 和 `WEBADMIN_*`；
- VPN 端的 `admin-domain.env` 设置：
  ```ini
  RELAY_HOST=scholarvpn.homes
  RELAY_TLS=1
  RELAY_TLS_NAME=scholarvpn.homes
  ```
  （私有 CA 时用 `RELAY_TLS_CA=/path/ca.pem` 替代 `RELAY_TLS=1`）

### 4.3 systemd（推荐）

当前公网服务器已安装三个 unit：

```text
scholarvpn-admin-relay.service
scholarvpn-admin-vpn.service
scholarvpn-admin-web.service
```

查看：

```bash
systemctl status scholarvpn-admin-relay scholarvpn-admin-vpn scholarvpn-admin-web
systemctl is-enabled scholarvpn-admin-relay scholarvpn-admin-vpn scholarvpn-admin-web
```

启动/停止/重启：

```bash
sudo systemctl start   scholarvpn-admin-relay scholarvpn-admin-vpn scholarvpn-admin-web
sudo systemctl stop    scholarvpn-admin-web scholarvpn-admin-vpn scholarvpn-admin-relay
sudo systemctl restart scholarvpn-admin-relay scholarvpn-admin-vpn scholarvpn-admin-web
```

日志：

```bash
journalctl -u scholarvpn-admin-relay -f
journalctl -u scholarvpn-admin-vpn -f
journalctl -u scholarvpn-admin-web -f
```

unit 文件（路径按实际仓库调整）：

```ini
# /etc/systemd/system/scholarvpn-admin-relay.service
[Unit]
Description=ScholarVPN Admin Relay (TLS)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/root/ScholarVPN/server
EnvironmentFile=-/root/ScholarVPN/server/admin-domain.env
ExecStart=/root/ScholarVPN/server/admin-relay.sh fg
ExecStop=/root/ScholarVPN/server/admin-relay.sh stop
Restart=always
RestartSec=3
TimeoutStopSec=20

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/scholarvpn-admin-vpn.service
[Unit]
Description=ScholarVPN Admin VPN-side (admin_server + admin_agent)
After=network-online.target scholarvpn-admin-relay.service
Wants=network-online.target scholarvpn-admin-relay.service

[Service]
Type=simple
WorkingDirectory=/root/ScholarVPN/server
EnvironmentFile=-/root/ScholarVPN/server/admin-domain.env
ExecStart=/root/ScholarVPN/server/admin-vpn.sh fg
ExecStop=/root/ScholarVPN/server/admin-vpn.sh stop
Restart=always
RestartSec=3
TimeoutStopSec=20

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/scholarvpn-admin-web.service
[Unit]
Description=ScholarVPN Admin Web (HTTPS)
After=network-online.target scholarvpn-admin-relay.service
Wants=network-online.target scholarvpn-admin-relay.service

[Service]
Type=simple
User=root
WorkingDirectory=/root/ScholarVPN/tools/webadmin
EnvironmentFile=-/root/ScholarVPN/server/admin-domain.env
ExecStart=/root/ScholarVPN/server/start-admin-web.sh
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=false
ReadWritePaths=/root/ScholarVPN/server/logs /root/ScholarVPN/server/run

[Install]
WantedBy=multi-user.target
```

安装：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now \
  scholarvpn-admin-relay.service \
  scholarvpn-admin-vpn.service \
  scholarvpn-admin-web.service
```

### 4.4 不用 systemd 的手动启停

```bash
cd /root/ScholarVPN/server

./admin-relay.sh start       # 后台启动 vpn_controller（自动读 admin-domain.env）
./admin-relay.sh fg          # 前台运行，Ctrl+C 干净退出
./admin-relay.sh stop
./admin-relay.sh restart
./admin-relay.sh status
./admin-relay.sh logs
./admin-relay.sh doctor
./admin-relay.sh token       # 打印中转管理令牌
./admin-relay.sh add-agent <64位指纹>
./admin-relay.sh list-agents
```

网页：

```bash
cd /root/ScholarVPN/server
./start-admin-web.sh          # 前台；Ctrl+C 退出
# 后台：
nohup ./start-admin-web.sh >> logs/webadmin.log 2>&1 &
```

网页地址：

```text
https://scholarvpn.homes/
```

首次部署（数据库里还没有管理员时）：

```bash
cd /root/ScholarVPN/tools/webadmin
python3 manage.py create-admin admin
# 交互输入密码（至少 10 位）
```

然后打开 `https://scholarvpn.homes/login` 登录：

- 右上角“账号”：修改自己的密码（改密后所有会话失效，需重新登录）；
- 右上角“管理员”：添加其他管理员；
- 右上角“退出”：注销；
- 忘记密码：`python3 manage.py reset-password <用户名>`。

> 网页没有注册入口；首个管理员只能由服务器 root/有数据库权限的用户用
> `manage.py` 创建。

### 4.5 中转端验证

```bash

# 证书链
openssl s_client -connect scholarvpn.homes:443 \
  -servername scholarvpn.homes -verify_return_error </dev/null 2>&1 | \
  grep -E 'subject=|issuer=|Verify return code'

# 网页
curl -sS -o /dev/null -w '%{http_code}\n' https://scholarvpn.homes/

# 不带令牌应为 401
curl -sS -o /dev/null -w '%{http_code}\n' https://scholarvpn.homes/api/servers

# agent 列表
./admin-relay.sh status
```

## 5. 角色二：VPN 端部署

以下命令在 VPN 服务器上执行。当前与中转端同机，所以路径相同。

### 5.1 数据面 `vpn_server`

构建：

```bash
cd /root/ScholarVPN/server
cmake --build build --target vpn_server -j"$(nproc)"
```

首次启动/后台常驻：

```bash
cd /root/ScholarVPN/server
sudo ./start.sh -d          # 后台 + watchdog，异常自动重启
sudo ./start.sh status
sudo ./start.sh logs
sudo ./start.sh stop
sudo ./start.sh restart
```

前台调试：

```bash
sudo ./start.sh
```

安装为 systemd 服务（推荐生产）：

```bash
sudo ./start.sh install
systemctl status vpn-server
```

默认监听：

```text
0.0.0.0:51820  UDP + TCP
TUN: vpn0 / 10.8.0.1/24
```

> `vpn_server` 是数据面，重启会断开在线客户端。后台管理升级时不要重启它。

### 5.2 管理面 `admin_server` + `admin_agent`

配置 `admin-domain.env`（VPN 端）：

```ini
# 同机中转
RELAY_HOST=127.0.0.1
RELAY_TLS=1
RELAY_TLS_NAME=scholarvpn.homes

# 分离部署时改成：
# RELAY_HOST=scholarvpn.homes
# RELAY_TLS=1
# RELAY_TLS_NAME=scholarvpn.homes
# 私有 CA：
# RELAY_TLS_CA=/path/private-ca.pem
```

命令：

```bash
cd /root/ScholarVPN/server

./admin-vpn.sh start        # 后台启动 admin_server + admin_agent
./admin-vpn.sh fg           # 前台运行，Ctrl+C 一起退出
./admin-vpn.sh stop
./admin-vpn.sh restart
./admin-vpn.sh status
./admin-vpn.sh logs admin_agent
./admin-vpn.sh logs admin_server
./admin-vpn.sh logs all
./admin-vpn.sh doctor
./admin-vpn.sh fingerprint  # 本机身份指纹
./admin-vpn.sh token        # 本机 AdminServer 管理令牌
./admin-vpn.sh build
./admin-vpn.sh rebuild
```

监听：

```text
admin_server: 127.0.0.1:18080
admin_agent:  出站连接 <RELAY_HOST>:19090（TLS）
```

### 5.3 首次接入中转

1. 在 VPN 端取指纹：

```bash
cd /root/ScholarVPN/server
./admin-vpn.sh fingerprint
```

2. 在中转端登记：

```bash
cd /root/ScholarVPN/server
./admin-relay.sh add-agent <上一步的64位指纹>
```

3. 启动 VPN 管理面：

```bash
./admin-vpn.sh start
```

看到 `admin_agent 已接入中转` 即成功。若提示 `指纹不在白名单里`，回到第 2 步。

### 5.4 VPN 端验证

```bash
cd /root/ScholarVPN/server

./admin-vpn.sh status
./admin-relay.sh status          # 在中转端执行，看 agent 是否在线
sudo ./start.sh status           # 数据面
ss -ltnp | grep -E ':(51820|18080)\b'
```

本机管理页（浏览器/curl）：

```text
http://127.0.0.1:18080/
```

远程访问用 SSH 隧道：

```bash
ssh -L 18080:127.0.0.1:18080 root@<VPN服务器IP>
# 然后本机浏览器打开 http://127.0.0.1:18080/
```

### 5.5 命令行 `admin_cli`

在 VPN 端本机使用（令牌从环境变量读，避免进 shell history）：

```bash
cd /root/ScholarVPN/server
export ADMIN_TOKEN="$(./admin-vpn.sh token)"

./build/admin_cli info          # 公钥/IP/端口
./build/admin_cli list          # 未消费注册令牌
./build/admin_cli gen 5         # 申请 5 个
./build/admin_cli del <token>   # 删除指定令牌
```

## 6. 角色三：客户端

### 6.1 Windows 客户端

配置文件：

```text
%APPDATA%\ScholarVPN\config.ini
```

示例：

```ini
[Server]
Count=1

[Server1]
Name=ScholarVPN
ServerIP=154.36.166.113
ServerPort=51820
Transport=0
ClientID=user1
RegisterToken=
ServerPubKey=
```

字段说明：

| 字段 | 说明 |
|---|---|
| `ServerIP` | **VPN 服务器公网 IP**，不是中转域名 |
| `ServerPort` | `51820` |
| `Transport` | `0`=UDP（默认），`1`=TCP（UDP 被运营商丢包时） |
| `ClientID` | 显示名，任意，≤255 字节 |
| `RegisterToken` | 首次注册填管理员发的令牌，成功后自动清空 |
| `ServerPubKey` | 可选；留空用客户端内置服务器公钥 |

操作顺序：

1. 在中转网页 `https://scholarvpn.homes/` 用管理员账号登录；
2. 选择服务器 `vpn-1`；
3. 申请 1 个注册令牌并复制；
4. 填进客户端 `RegisterToken`；
5. 以管理员身份运行客户端，连接。

> 如果服务端 `keys/server_sig.key` 换过，客户端的 `ServerPubKey` 或内置公钥
> 也要同步更新，否则握手验签失败。

### 6.2 Android 客户端

在 App 的服务器设置里新增卡片：

- 地址：`154.36.166.113`
- 端口：`51820`
- 传输：UDP（默认）/ TCP
- 注册令牌：网页申请的令牌

保存后连接。

### 6.3 客户端验证连接

客户端侧看日志/状态是否显示已连接；服务端：

```bash
cd /root/ScholarVPN/server
sudo ./start.sh status
sudo ./start.sh logs
```

能看到客户端握手/分配虚拟 IP 的日志即正常。

### 6.4 中转网页管理（管理员）

打开：

```text
https://scholarvpn.homes/
```

- 首个管理员在服务器用 `python3 manage.py create-admin <用户名>` 创建；
- 用管理员账号登录 `https://scholarvpn.homes/login`；
- 左侧选择 `vpn-1`；
- 可查看公钥、申请/删除未消费注册令牌、导出 JSON；
- 生成的令牌是给客户端首次注册用的；
- 右上角“账号”修改自己的密码；右上角“管理员”添加其他管理员。

> 网页没有注册入口。中转管理令牌只由 webadmin 在服务端使用
> （访问 127.0.0.1:18081），浏览器永远拿不到。
> 密码使用 scrypt 哈希，会话/CSRF/登录限速都由 webadmin 处理。

## 7. 证书续期

### 7.1 手工证书（当前 DigiCert）

证书到期前从服务商下载新证书，上传后执行：


## 9. 排障

### 网页打不开 / 502

```bash
ss -ltnp | grep ':443 '
systemctl status scholarvpn-admin-web
journalctl -u scholarvpn-admin-web -n 50 --no-pager
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18081/api/servers
```

- 443 被占用：`ss -ltnp | grep ':443 '`，改用其他端口或停冲突服务。
- webadmin 起来了但 API 502：`vpn_controller` 没起或 18081 不对。

### 网页能开，但一直 401

- 401 通常表示**登录会话过期/未登录**，重新打开 `/login`；
- 登录失败连续 5 次会返回 429，等待 15 分钟或换账号；
- 管理员账号在 `tools/webadmin/data/webadmin.db`，忘记密码用
  `python3 tools/webadmin/manage.py reset-password <用户名>`；
- 502/网络错误检查 webadmin 与 `vpn_controller` 是否都在跑。

### 页面显示 agent offline / 503

```bash
# 中转端
./admin-relay.sh status
./admin-relay.sh logs

# VPN 端
./admin-vpn.sh status
./admin-vpn.sh logs admin_agent
```

常见原因：

| 现象 | 处理 |
|---|---|
| `连接 controller 失败` | `RELAY_HOST/RELAY_PORT` 不对、19090 防火墙没放行 |
| `准入被拒: pubkey not in whitelist` | 指纹没登记：中转端 `add-agent <指纹>` |
| `TLS 握手失败: hostname mismatch` | `RELAY_TLS_NAME` 与证书域名不一致 |
| `certificate verify failed` | 公共 CA 用 `RELAY_TLS=1` 且系统有 `ca-certificates`；私有 CA 用 `RELAY_TLS_CA` |
| 反复断开重连 | 检查证书时间、19090 链路、controller 是否在跑 |

### 证书链不完整

浏览器/客户端报 `unable to get local issuer certificate`：

- 确认 `tls/fullchain.pem` 是 **叶证书 + 中间证书**；
- 云厂商下载包通常有 `chain.crt`/`ca_bundle.crt`，用
  `install-admin-cert.sh domain cert.pem key.pem chain.pem` 合并；
- 验证：

```bash
openssl verify -CAfile /etc/ssl/certs/ca-certificates.crt \
  -untrusted tls/fullchain.pem tls/fullchain.pem
```

### 8443 被占用

当前公网服务器的 8443 是 **Node 代理**（`scholarvpn.service`），不要动它。
管理网页用 443；如果 443 也被占用，再换端口并放行防火墙。

### 客户端连不上

- `ServerIP` 是否是 **VPN 服务器公网 IP**；
- 云安全组/防火墙是否放行 `51820/udp` 和 `51820/tcp`；
- `sudo ./start.sh status` 看数据面；
- UDP 不通时客户端切 TCP（`Transport=1`）；
- 注册令牌是否已被使用/过期。

## 10. 安全清单

- [ ] 私钥权限 `600`，`server/tls/` 权限 `700`，证书目录不入 Git；
- [ ] 18080/18081 只绑 `127.0.0.1`，公网不放行；
- [ ] 19090 是 TLS，但仍需防火墙限制来源；
- [ ] 网页不开放注册；首个管理员由服务器 `manage.py create-admin` 创建，后续账号由已登录管理员添加；
- [ ] 中转管理令牌只在服务端使用，不写进浏览器/文档/聊天；VPN 管理令牌分开保管；
- [ ] 管理员密码 ≥10 位，使用独立强密码；数据库 `tools/webadmin/data/` 权限 700、DB 600，定期备份；
- [ ] 服务器 root 改强密码，配置 SSH 密钥，考虑禁用密码登录；
- [ ] 证书到期前续期并验证；
- [ ] 定期备份 `server/keys/`、`server/agents.txt`、`server/relay_admin_token.txt`、
  `server/tls/`（离线加密保存）。
